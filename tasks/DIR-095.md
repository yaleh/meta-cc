## Finding

During the 2026-07-30 dogfooding analysis session, a "last 2 days" question produced whole-corpus (5-day) statistics, silently mixing time windows in the report. Root cause: `analyze_errors`, `analyze_bugs`, `quality_scan`, `get_work_patterns`, and `get_tech_debt` accept NO `since`/`until` parameters.

DIR-021 (done) fixed since/until for role=assistant content queries, but the five analysis tools remain uncovered. `query_session_signals` and `get_timeline` already support RFC3339 `since`/`until`, so the filtering vocabulary exists — it is simply not wired into the analyzers.

Compounding evidence from the same session: `query_sessions` hard-failed with `MCP error -32603: provider claude: no Claude entries in /home/yale/.claude/projects/-home-yale-work-meta-cc/8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl` (tolerance fix tracked in DIR-094). Without time-window parameters there was no way to re-run the analysis against a known time-bounded subset.

## Dependencies

Follows DIR-021 (done, since/until for content queries). Complementary to DIR-094 (tolerant loading); not a duplicate of either.

## Scope
owner_repo: meta-cc

Add RFC3339 `since`/`until` to the five analysis tools with the same semantics as the existing `query_session_signals`/`get_timeline` parameters (since inclusive, until exclusive). Filtering happens before aggregation, so `stats_only`/`stats_first` outputs honor the window. Invalid timestamps yield `mcerrors.ErrInvalidInput`, never a crash.

## Implementation Notes

Recorded by the DIR-095 worker at commit `581cafa` on branch `task/DIR-095`.

**AC-3 / `stats_first` — read this before accepting AC-3 at face value.** `stats_only` is
fully implemented and verified: the window is applied before aggregation, so every
aggregate covers only the in-window records.

`stats_first` does **not** exist on these five tools, and this task did not add it.
DIR-048 deliberately scopes `stats_first` to the four pipeline-routed query tools,
because the six analysis tools return typed non-flat analyzer results and dispatch
past the response pipeline that implements it. Passing `stats_first` to any of the
five is therefore rejected as an unknown parameter — which is the honest reading of
AC-3's "stats_first" clause here, and is strictly better than the failure mode the
Finding describes: the parameter is refused loudly rather than silently ignored
while the tool answers from the whole corpus.

`TestAnalysisTools_RejectUndeclaredStatsFirst` (in `internal/mcp/executor`) pins that
boundary so it cannot regress into a silent no-op. Making AC-3's `stats_first` clause
literally true would require extending DIR-048's scoping decision, which is out of
this task's scope and Touches.

**Evidence, per AC:**

- AC-1 — `TestAnalysisToolsHonorSinceUntilWindow` (service layer, all five tools) and
  `TestAnalysisTools_HonorWindow_EndToEnd` (real `ExecuteTool` dispatch, all five).
  Both assert the windowed run differs from the unwindowed run *and* is JSON-equal to
  a run over a separately-seeded subset corpus, so a filter that does nothing fails.
- AC-2 — `TestAnalysisToolsRejectInvalidSinceUntil` (5 tools x 3 malformed values),
  `TestAnalysisTools_RejectInvalidWindow_EndToEnd` (through the tool boundary),
  `TestApplyTimeWindowSemantics`, `TestFilterEntriesByTimeRangeRejectsInvalidBounds`,
  and `TestAnalysisToolsInvalidBoundOutranksMissingCorpus` (a malformed bound is
  reported as `ErrInvalidInput` even when pointed at an empty corpus, proving the
  verdict comes from the parameter rather than a failed lookup).
- AC-3 — `TestAnalysisToolsStatsOnlyHonorsSinceUntilWindow`,
  `TestAnalysisTools_HonorWindow_StatsOnly_EndToEnd`, and the `stats_first` boundary
  proof above.
- AC-4 — `docs/guides/mcp.md`: `since`/`until` rows added to the Standard Parameters
  table, a new `### since/until time windows` section (inclusive/exclusive semantics,
  the sentinel error, before-aggregation ordering, the `get_tech_debt`/`source_dir`
  boundary), a note under Analysis Tools naming the five newly-covered tools, and a
  scout-step example. The DIR-078 documentation contract check passes in `make commit`.

A falsification check was run before commit: short-circuiting `applyTimeWindow` to a
no-op turned both service-layer window tests red, confirming they are load-bearing.
`make commit` passes (exit 0, all packages green) and `go test -short ./...` is green
across 44 packages.
