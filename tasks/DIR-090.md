## Finding

`make commit` is the acceptance gate for 33 of the last 36 tasks and costs ~62s per run. Gate-events since 2026-07-28 record 79 acceptance runs (~82 min total wait), with heavy retries: DIR-056 ran acceptance 9 times, DIR-053 5 times, DIR-058 4 times. Most retries were fix-compile-rerun cycles that a fail-fast check on the touched package would have shortened to seconds. Early tasks DIR-005/006/007 already proved the pattern: hand-written scoped acceptance commands like `go test ./internal/mcp/executor/... && go build .` ran in <10s and were targeted. The fleet later standardized on full `make commit`, losing the fast inner loop.

## Dependencies

None.

## Scope

Add a Makefile target for scoped, fail-fast iteration checks and document a two-stage acceptance workflow: scoped tests during iteration, full `make commit` before promotion. Per-task acceptance strings in this repo may reference the new target. Changes to the quay loop-driver skill itself are explicitly out of scope — it lives in a different repository (Quay Workspace Boundary). No source code changes.

## Plan

1. Add a `test-scoped` target to the Makefile: `test-scoped: ` runs `go test -short $(PKGS)` followed by `go build ./...`, with `PKGS` defaulting to `./...` when unset.
2. Register the target in the `make help` output with a one-line description, matching the existing help style.
3. Document the two-stage acceptance workflow in `docs/guides/plugin-development.md` (or new `docs/guides/testing.md`): stage 1 `make test-scoped PKGS=./internal/<pkg>/...` during iteration; stage 2 full `make commit` before promoting a task to ready/done. Cite the DIR-005/006/007 precedent and the 2026-07-30 gate-events numbers.
4. Note in the docs that per-task `extra.acceptance` strings may use `make test-scoped PKGS="..."` for scoped gates, with `make commit` retained as the promotion gate.
5. Add a quick link / FAQ entry in `CLAUDE.md` pointing at the two-stage workflow doc.
