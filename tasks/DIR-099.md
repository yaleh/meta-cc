## Finding

Structural root cause from the 2026-07-30 dogfooding session: DIR-018 (done) fixed skip-and-report tolerance in the analysis `loadData` path, but that behavior was lost/not propagated when DIR-032/DIR-034 rewrote and re-wired the ListSessions path behind `query_sessions` — a corrupt file (`8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl`, empty/truncated) hard-crashed `query_sessions` twice. There is NO mechanical enforcement that every session-corpus-consuming tool tolerates malformed files.

This is the same declared-but-not-wired drift class that DIR-041..DIR-045 addressed for schema parameters, and that DIR-045 crystallized into a static gate. The tolerance contract lives in DIR-018's precedent and DIR-094 (sibling); this task crystallizes it into a regression gate that covers every corpus-consuming tool mechanically, so the next ListSessions-style rewrite cannot silently drop tolerance again.

## Dependencies

DIR-094 (sibling task) should land first — this gate codifies that contract.

## Plan

1. Build a shared corrupt-corpus fixture in `internal/testutil/`: one empty file, one truncated JSONL, one wrong-shape file.
2. Add a table-driven regression test that runs EVERY session-corpus-consuming tool against the fixture and asserts "non-empty result + warning naming the bad file".
3. Structure the table so any newly added tool is registered in one place (one registry entry per tool, named).
4. Verify the test runs under `go test -short` (the `make commit` path) within a few seconds.
5. Negative demonstration: add a scratch tool that lacks tolerance, show the test fails for it, then remove the scratch tool.
6. Document how to register a new corpus-consuming tool in the table.

### AC1 — negative demonstration

A scratch corpus-consuming tool was registered (`dir099_scratch_intolerant`, gate entry + `BuildTool` + `registerHandler`) and the gate run against it twice, once per failure mode of the DIR-094 defect. Both went red for the intended reason; the scratch tool was then removed.

Whole-batch failure (one unusable file fails the call):

```
--- FAIL: TestCorpusToleranceGate/dir099_scratch_intolerant
    Error: Received unexpected error:
           provider claude: no Claude entries in corpus (whole-batch failure on one unusable file)
    Messages: a corpus containing an unusable session file must not fail the whole call
```

Silent loss (the call succeeds, the results are simply gone, nothing is named):

```
--- FAIL: TestCorpusToleranceGate/dir099_scratch_intolerant
    Messages: the skip must be reported, not silent
    [... skipped 8eda8f4e-2c74-4176-ba6b-8c45e890df42 without naming it anywhere in the response;
         a silently shorter result set is the DIR-018 contract violation this gate exists to catch
     ... skipped dir099-truncated without naming it ... ; ... skipped dir099-wrong-shape without naming it ...]
    Messages: a dirty corpus must expose skipped_files;
              got: {"data":[],"mode":"inline","pagination":{...},"warnings":[]}
```

Removal verified: `grep -rn 'dir099_scratch_intolerant\|dir099ScratchGate' --include=*.go .` returns no matches (exit 1), and the gate is green again afterwards. The permanent `TestCorpusToleranceGate_RejectsAnIntolerantTool` keeps both failure modes under test without any scratch artifact.

### AC4 — three corruption shapes

`testutil.CorruptFiles()` returns exactly three entries, one per shape, each with a `Name` (the session ID it is installed under) and a `Why`:

| Shape | File | Bytes | Fails at |
| --- | --- | --- | --- |
| `empty` | `corrupt-empty.jsonl` | 0 | parses with **no error**, zero entries — the silent-loss case |
| `truncated` | `corrupt-truncated.jsonl` | 106 | a parse error (line cut mid-object) |
| `wrong-shape` | `corrupt-wrong-shape.jsonl` | 39 | valid JSON, wrong record shape — a parse error by a different route |

The reporting tools assert all three shapes via `allCorruptShapes()`, so the set cannot silently shrink when the fixture grows.

### `make commit`

Green, including the DIR-078 documentation contract check (the new guide's relative links resolve) and `go test -short ./...`.

### Recorded departures from the full contract

The gate records, per tool, how far tolerance actually reaches today rather than asserting a uniformity that does not hold. Three tools (`query_session_content`, `query_session_signals`, `query_file_activity`) return the usable session's results but do not name what they skipped — `kindEnumerationSilent`, with a `note` on each entry. Five (`get_session_directory`, `get_session_metadata`, `inspect_session_files`, `execute_stage2_query`, `query_edit_sequences`) have response shapes that are not corpus result sets and supply their own assertion. Closing the reporting gap for the silent three is a behavior change in production code and is **not** in this task's Touches.
