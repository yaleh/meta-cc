## Finding

(Original, 2026-07-25) Claude Code Workflow scripts run in a Bun-compiled JS runtime WITHOUT access to the Claude Code tool API: calling `Skill()`, `Agent()`, `Bash()`, etc. from a workflow script throws `ReferenceError: <tool> is not defined`. Observed live: a run-routines workflow wrapping `Skill({skill:"quay:run-routines"})` crashed in 24ms. The bridge is one-way: Skills may dispatch workflows; workflows can only dispatch subagents via the workflow DSL.

(Re-scoped 2026-07-30) Two parts of the original task are done or moved: the quay canonical `run-routines.js` no longer calls `Skill()` (fixed in the quay repo, out of meta-cc scope), and ADR-007 is taken by `ADR-007-provenance-data-source.md`. What remains IN meta-cc scope:

1. **Stale workflow copies**: `/home/yale/work/meta-cc/.claude/workflows/run-routines.js` still calls `Skill()` (lines 15-18) and WILL crash if invoked; `.claude/workflows/drain-directives.js` is older than the quay canonical copy (missing `$a` args normalization). These copies must be re-synced from `/home/yale/work/quay/plugin/workflows/`.
2. **ADR not yet written**: the one-way Workflow→Skill isolation constraint is still undocumented in meta-cc's ADR set. It must be ADR-008 (ADR-007 is occupied).
3. Workflow lint rules belong to the quay generator — out of scope, reported only.

## Proposal

1. Sync `.claude/workflows/*.js` from the quay canonical plugin copies (verify each against `/home/yale/work/quay/plugin/workflows/`; do not hand-edit semantics).

Register it in the quay ADR store if DIR-009 has landed (frontmatter format); otherwise plain markdown + a note.
