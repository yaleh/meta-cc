## Finding

Codex documentation currently mixes three different contracts. Transcript discovery is described as honoring `CODEX_HOME`, the provider locator currently uses `META_CC_CODEX_ROOT` and a fixed `state_5.sqlite`, and `docs/reference/codex-app-server.md` implies both overrides already affect the locator. Installation material also does not present one end-to-end user-scope upgrade and cache-refresh flow. Finally, examples describe Claude as the implicit provider even though DIR-073 will make the active host the default.

## Dependencies

- DIR-069 defines the final Codex home and evolving state database discovery contract.
- DIR-070 defines safe Codex plugin-cache upgrade behavior.
- DIR-073 defines host-aware provider omission behavior.

This task documents the behavior after those implementations land; it must not publish their intended behavior as if it already exists.

## Plan

1. Establish one environment-variable precedence table shared by transcript, SQLite, rollout-only, and app-server paths.
2. Document backend selection and fallback in observable user terms, including diagnostics and limitations.
3. Document user-scope install and upgrade steps, cache invalidation, restart expectations, and verification commands for Codex.
4. Explain provider omission separately for Claude Code and Codex hosts, while preserving explicit override examples.
5. Cross-link install, query, app-server, and history-model references.

## Acceptance Criteria

- [ ] All current docs agree on Codex root precedence, database discovery, and rollout-only fallback.
- [ ] The app-server reference distinguishes implemented behavior from fallback and known limitations.

- [ ] Provider omission is documented as active-host selection only after DIR-073 implements it.
