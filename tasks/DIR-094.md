## Finding

During the 2026-07-30 dogfooding analysis session, `query_sessions` hard-failed TWICE with:

```
MCP error -32603: provider claude: no Claude entries in /home/yale/.claude/projects/-home-yale-work-meta-cc/8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl
```

One empty/truncated session file blocked ALL session listing, forcing a workaround via `get_timeline` + `query_session_content`. `query_sessions` is the CLAUDE.md decision-tree entry point, so the standard workflow was dead on arrival.

Git HEAD on main has since landed `abc8135 fix(provider): handle zero-message session stubs in ListSessions and sessionFromFile` — the point fix for the ListSessions hard-fail (the analysis session's failure likely came from a stale installed MCP binary predating abc8135). DIR-018 (done) established skip-and-report semantics for `loadData` in `internal/analysis/service.go`. What remains unproven: that abc8135's tolerance covers every corpus-enumerating path, and silent tolerance is not the DIR-018 contract — callers still cannot see which files were skipped.
