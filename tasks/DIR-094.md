## Finding

During the 2026-07-30 dogfooding analysis session, `query_sessions` hard-failed TWICE with:

```
MCP error -32603: provider claude: no Claude entries in /home/yale/.claude/projects/-home-yale-work-meta-cc/8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl
```

One empty/truncated session file blocked ALL session listing, forcing a workaround via `get_timeline` + `query_session_content`. `query_sessions` is the CLAUDE.md decision-tree entry point, so the standard workflow was dead on arrival.

Git HEAD on main has since landed `abc8135 fix(provider): handle zero-message session stubs in ListSessions and sessionFromFile` — the point fix for the ListSessions hard-fail (the analysis session's failure likely came from a stale installed MCP binary predating abc8135). DIR-018 (done) established skip-and-report semantics for `loadData` in `internal/analysis/service.go`. What remains unproven: that abc8135's tolerance covers every corpus-enumerating path, and silent tolerance is not the DIR-018 contract — callers still cannot see which files were skipped.

## Evidence

Every path below was exercised with the full `go test ./...` suite, green in the worktree both before and after `git merge develop`.

- **AC1** — `internal/analysis/service_skipped_files_test.go::TestLoadDataTolerance_EveryPathReturnsResultsPlusWarning` runs all six corpus-enumerating analysis paths (`get_timeline` plus the five analysis tools) over a corpus containing the 0-byte `8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl` and three further zero-message/malformed shapes, asserting per path: (a) the valid session's results ARE present — distinguishable from a zero-message-only baseline; (b) those results are IDENTICAL to a clean-corpus control, proving the bad file neither erased nor altered them; (c) a warning names every skipped file; (d) `skipped_files` lists every skipped path. `TestLoadDataTolerance_StatsOnlyPathsAlsoReport` (stats_only short-circuit), `_CleanCorpusOmitsExclusionMetadata` (clean-corpus wire shape) and `_SessionScopeNamedEmptyFile` (exact-session selector) cover the remaining branches. `internal/mcp/executor/query_sessions_tolerance_test.go` drives the `query_sessions`/ListSessions path end-to-end through `ExecuteTool`, asserting against the SERIALIZED response rather than an intermediate struct. `internal/provider/claude/provider_skips_test.go` covers the provider layer underneath it.
- **AC2** — the previously-fatal classes now skip-and-report instead of failing the batch: `provider.ListSessions` no longer aborts on a non-sentinel per-file error (`TestListSessionsToleratesAndReportsUnreadableFile` makes the read fail with EISDIR via a directory named `unreadable.jsonl`); `loadData` no longer drops a zero-message file without trace (it parsed with no error, which is why the old code never noticed); and `loadProviderData` now adopts the per-session warnings `providerrecords.Build` had already computed and this caller discarded one frame later. Every test above asserts `NoError` over a dirty corpus.
- **AC3** — `skipped_files` travels the whole response path: `locator.SkipReport` → `QueryResult.SkippedFiles` → `pipeline.InjectWarningsAndSkippedFiles` on the query side (unit-tested by `TestInjectWarningsAndSkippedFiles_AddsPathList` / `_OmitsEmptyPathList`) and `marshalResult` on the analysis side. `warnings` stays always-present (DIR-018); `skipped_files` is omitted entirely for a clean corpus, so that response is byte-identical to before.
- **AC4** — `internal/analysis/testdata/dir094/` holds the checked-in corpus (valid control, 0-byte, metadata-only stub, malformed JSON, whitespace-only) plus a README documenting each shape and why it exists. The control session deliberately carries a TODO marker and an error→fix pair, so `get_tech_debt` and `analyze_bugs` produce real signal and "results present" is a genuine assertion for every tool.
- **AC5** — `docs/guides/troubleshooting.md` → "Malformed session file tolerated but no warning appears" documents the refresh requirement: an installed plugin binary must be refreshed via `make stage` / `make install-user` (project scope: `make install-local`; Codex registration: `make install-user-codex`) before any of this is observable, because a running MCP server keeps serving the binary installed when it started. The fixture README repeats the pointer. This applies to validating this task's own fix from Claude Code.
