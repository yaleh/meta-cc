## Finding

During the 2026-07-30 dogfooding analysis session, `query_sessions` hard-failed TWICE with:

```
MCP error -32603: provider claude: no Claude entries in /home/yale/.claude/projects/-home-yale-work-meta-cc/8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl
```

One empty/truncated session file blocked ALL session listing, forcing a workaround via `get_timeline` + `query_session_content`. `query_sessions` is the CLAUDE.md decision-tree entry point, so the standard workflow was dead on arrival.

Git HEAD on main has since landed `abc8135 fix(provider): handle zero-message session stubs in ListSessions and sessionFromFile` — the point fix for the ListSessions hard-fail (the analysis session's failure likely came from a stale installed MCP binary predating abc8135). What remains unproven: that abc8135's tolerance covers every corpus-enumerating path, and silent tolerance is not the DIR-018 contract — callers still cannot see which files were skipped.

## Rebuild Requirement

The MCP server is a **compiled Go binary** installed into the Claude Code plugin directory; editing the source does not change what a running session executes. This fix is only observable after refreshing the installed binary with `make stage` (or `make install-user` for a user-scope install) and restarting the MCP server. A fix can be present on `main` and still be absent from a running session — the 2026-07-30 `query_sessions` failure that opened this task was itself observed from an installed binary that predated the `abc8135` point fix. See the same note in `docs/guides/mcp-query-tools.md` (`### query_sessions`).

## Evidence

One shared rule now decides, for every corpus-enumerating path, whether an enumerated session file contributed anything: `internal/locator/sessionfile.go` — `ErrNoMessageEntries`, `SessionFileExclusion`, `ExclusionFor(file, entryCount, parseErr)`. It takes the parse *outcome* rather than owning the parse, because the two consumers intentionally use different parsers (Claude's tolerant line-skipping vs. analysis's line-numbered errors); unifying the parsers would have been an unrelated behavioral change.

Per-path verification, all against the checked-in `tests/fixtures/malformed-corpus/` (healthy + empty + metadata-only stub + truncated JSON), each path asserted in **both** halves — results survive AND every excluded file is named:

- **`ListSessions`** — `TestListSessionsReportsEveryExcludedFile` (`internal/provider/claude/provider_test.go`). Was fail-fast on a genuinely unreadable file, and a silent `continue` on a zero-message stub (the `abc8135` half-fix); now skips and records both. `sessionFromFile` deliberately keeps the empty-vs-I/O-error distinction, since it backs targeted lookups where there is no rest-of-batch to protect.
- **`query_sessions`** — `TestQuerySessions_Claude_OneBadFileDoesNotEraseTheRestAndIsNamed` (`internal/mcp/executor/query_sessions_handler_test.go`). Was `MCP error -32603: provider claude: no Claude entries in <file>`; now lists the healthy session and folds `Provider.Warnings()` into the response `warnings`.
- **`get_timeline` + `analyze_errors` / `analyze_bugs` / `quality_scan` / `get_work_patterns` / `get_tech_debt`** — `TestLoadDataWarnings_EveryCorpusPathReportsExcludedFiles` (`internal/analysis/service_warnings_test.go`), six subtests. `loadData` warned only on parse errors, so the empty-file case — the actual `8eda8f4e` shape, which parses cleanly — was still dropped in silence; it now applies the shared rule. `loadProviderData` no longer discards `providerrecords`' per-session warnings on the codex/all path, and threads provider `Warnings()` through instead.
- **Aggregators** (`Registry.MergedSessions`, `providerrecords.Build`) still return the first `ListSessions` error, but that path is no longer reachable for a single bad Claude file, since `ListSessions` now returns a nil error for every per-file exclusion. Codex's `filesListSessionsFiltered` already skipped-and-warned per row (out of scope; no change).

Non-vacuity: the results half of the per-tool test is guarded by `TestCorpusMarkersRequireTheHealthySession`, which re-runs the same table against the corpus with `healthy.jsonl` removed and asserts every session-derived marker disappears. Without it, a marker matching a zero-valued field would keep passing after the healthy session stopped reaching the analyzer, and the regression would be silent again. `analyze_bugs` and `get_tech_debt` needed the fixture extended (an error→success `Read` pair whose successful output carries a `// TODO:` comment) before they emitted any session-derived output at all — with the original fixture both returned empty structures with *or* without the healthy session.
