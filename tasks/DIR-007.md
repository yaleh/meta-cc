## Finding

In `internal/mcp/pipeline/pipeline.go:247-254`, `BuildStatsFirstResponse` calls `querypkg.GenerateStats` / `GenerateTimestampStats` / `GenerateSessionStats` but discards the error with `_`. Compare with `BuildStatsOnlyResponse` (lines 204-210 of the same file) which properly checks and returns errors. If stats generation fails, the response has an empty or malformed stats section with no error indication. The caller sees a "success" response with missing data.

## Proposal

Capture and return errors from stats generation functions in `BuildStatsFirstResponse`, consistent with the pattern already used in `BuildStatsOnlyResponse`. Log the error with `slog.Error` (matching the existing logging pattern at lines 240-245) and return an empty string with the error.

## Plan

1. Fix `internal/mcp/pipeline/pipeline.go:248-255` — replace `stats, _ = querypkg.Generate*Stats(jsonlData)` with proper error capture: `var err error; stats, err = querypkg.Generate*Stats(jsonlData); if err != nil { slog.Error(...); return "", err }`
2. Add test case for `stats_first` mode when stats generation fails — verify error is propagated, not silently swallowed
