## Finding

Measured 2026-07-30: the Makefile `test` target uses `-v`, producing very large logs. Session transcripts show agents universally pipe through `tail -40` / `grep "^--- FAIL"` to cope — pure token and I/O waste. `go test` without `-v` already prints failing tests and their output verbosely enough on red runs; green runs do not need the per-test stream. Context: 79 acceptance gate runs in 2 days (≈82 min total) make this overhead recurring.

## Dependencies

None

## Proposal

**What/Why**: The default `test` target (`Makefile:526-528`) runs `$(GOTEST) -short -v ./...` (Makefile:528), streaming per-test output on every invocation — including via `commit: check-essential check-no-scanner test` (Makefile:321) and `check-commit-ready: check-essential test` (Makefile:228), i.e. every acceptance gate run. `go test` without `-v` already prints failing packages and their full output on red runs, so the `-v` stream on green runs is pure log volume. Fix: strip `-v` from `test` and preserve it behind an opt-in `test-verbose` target.

**Approach**:

1. In `Makefile`, change the `test` recipe (Makefile:528) from `$(GOTEST) -short -v ./...` to `$(GOTEST) -short ./...`; keep the existing echo line and all other flags/package selection unchanged.
2. Add a new `test-verbose:` target immediately after `test:` whose recipe is the current line verbatim, `$(GOTEST) -short -v ./...`, with an echo marking it as the debug path.
3. Add `test-verbose` to the `.PHONY` list (Makefile:47), which today lists `test test-all test-coverage` but not `test-verbose`.
4. In `help:`, update the `make test` description (Makefile:764) to note compact (non-verbose) output, and add a `make test-verbose` line directly after it describing full per-test output for debugging.
5. Grep CLAUDE.md for `make test` / `-v` mentions; edit only if a line describes the current `-v` behavior (the Quick Links entry reads "Run tests only", so likely no change — leave the file untouched if none is warranted).
6. Verify both AC paths locally: a green `make test` produces compact output (≤200 lines), a deliberately failing test still names its package and test in default output, and `make test-verbose` still streams per-test lines.

**Out of scope**:

- The `-v` flags in `test-all` (Makefile:549), `test-coverage` (Makefile:555), and `test-coverage-full` (Makefile:560) — only the default `test` target's verbosity changes.
- Package selection, `-short`, coverage flags, or any behavior other than output verbosity.
- CI workflows or scripts that invoke `go test` directly; Touches are limited to Makefile (and CLAUDE.md only if needed).

**Risks**:

- Debugging ergonomics: a green run now shows only per-package `ok` lines, so progress/pass-count visibility in long runs drops; the mitigation is the discoverable `test-verbose` escape hatch via `make help`.
- Consumers that parse `=== RUN` per-test lines from `make test` output will need to switch to `make test-verbose` (observed `^--- FAIL` greps work in both modes).

## Scope

Change `test:` to `$(GOTEST) -short ./...` and add an opt-in `test-verbose` target that retains `-v` for debugging. Update `make help` accordingly. CLAUDE.md build/test quick-links are in scope only if they describe the current `-v` behavior. Do not change package selection or other flags — output verbosity only.
