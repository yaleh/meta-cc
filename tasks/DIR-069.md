## Finding

The provider locator still resolves only `META_CC_CODEX_ROOT` or `~/.codex` and hard-codes `state_5.sqlite`. This disagrees with transcript discovery, which honors `CODEX_HOME`, and with documentation that presents `CODEX_HOME` as a provider override. A custom Codex home can therefore expose rollout files to one path while the SQLite/app-server provider reads another home. A future Codex release using another `state_N.sqlite` name also makes the files backend unavailable. When SQLite is absent but rollout JSONL exists, project content remains undiscoverable through the provider.

## Contract

- Resolve one canonical Codex root with precedence `META_CC_CODEX_ROOT`, then `CODEX_HOME`, then the user default.
- App-server, SQLite metadata, raw-file discovery, and transcript lookup use that same root.
- Discover the highest compatible `state_N.sqlite` deterministically instead of assuming version 5.
- If no usable database exists, retain rollout-only discovery for active and archived session trees when enough transcript metadata exists to enforce cwd scope.
- An incompatible database produces an actionable warning and safe fallback, never a silent empty corpus or cross-project result.

## Plan

1. Centralize Codex root resolution and remove the current locator divergence.
2. Add deterministic state database enumeration and schema compatibility checks.
3. Add metadata-light recursive discovery for `sessions` and `archived_sessions` as the final files fallback.
4. Preserve cwd/session boundaries and provider provenance in every fallback.
5. Update documentation and add isolated fixtures for custom homes, multiple state versions, missing/corrupt databases, active history, and archives.

## Acceptance Criteria

- [ ] Setting only `CODEX_HOME` makes every Codex backend read that home.
- [ ] With `state_5.sqlite` and `state_6.sqlite`, the highest compatible database is selected deterministically.
- [ ] Rollout-only homes remain queryable without a SQLite database.
- [ ] Active and archived fallback discovery obey cwd and archived filters.
- [ ] Invalid databases degrade with warnings and never leak another project.
- [ ] Focused tests and `make commit` pass.
