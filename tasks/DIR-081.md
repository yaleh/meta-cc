## Finding

ADR-001 and ADR-003 no longer accurately describe the shipped architecture:

- ADR-001 defines a standalone `meta-cc` CLI as Layer 1, while Phase 26 removed
  the legacy CLI and established an MCP-only product architecture.
- ADR-001 and ADR-003 are Claude-centric, while the current system has
  provider-neutral conversation models and first-class Claude/Codex backends.
- ADR-003 lists a historical fixed set of 14 tools and a three-tier integration
  model whose commands/subagents and percentages are not a stable architectural
  contract.
- ADR-003 says MCP is the only data-access layer, while the metadata-driven
  design and ADR-004 also permit controlled file-reference and jq/Bash
  consumption. ADR-009 now defines the intended boundary more precisely.

Editing these accepted records in place would erase why the original decisions
were made. The project needs an explicit evolution decision.

## Scope

1. Audit ADR-001 and ADR-003 against the current binaries, provider model,
   plugin surfaces, and documented query workflows.
2. Draft a provider-neutral MCP-only architecture ADR that either supersedes
   ADR-001 and ADR-003 or supersedes only the portions proven obsolete.
3. Preserve the enduring decisions:
   - deterministic local data processing is separated from LLM interpretation;
   - MCP is the supported product integration and query boundary;
   - semantic interpretation remains in the host model/workflow layer.
4. Replace volatile inventories and use-case percentages with links to
   authoritative current references.
5. Reconcile the new decision with ADR-004 and ADR-009, including the controlled
   `file_ref`/jq escape hatch.
6. Update ADR lifecycle metadata, related-decision links, and the ADR index
   without rewriting the historical context of superseded records.

## Non-Goals

- Do not restore the removed legacy CLI.
- Do not change query behavior, provider selection, or plugin packaging as part
  of this documentation decision.
- Do not silently change accepted ADR text so it appears the 2025 decision
  anticipated the current architecture.

## Acceptance Criteria

- The current executable and integration architecture is described without a
  required legacy CLI layer.
- Claude and Codex are represented through a provider-neutral contract, with
  host-specific adapters treated as implementations.
- The new ADR explicitly states which parts of ADR-001/003 are preserved and
  which are superseded.
- ADR-001/003 statuses and links follow the repository ADR lifecycle convention.
- No active ADR contains a fixed tool inventory or unsupported percentage as an
  architectural requirement.
- ADR-004 and ADR-009 references are coherent with the MCP-only decision.
- ADR index and quay-native ADR listing agree.
- `make commit` passes.

## Dependencies

- ADR-009 must be available as the current query execution/result-consumption
  boundary before this architecture evolution is finalized.
