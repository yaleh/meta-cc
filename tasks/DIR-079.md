## Finding

Historical meta-cc usage across Claude Code and Codex shows that most queries are
self-contained, but the failures cluster at the expert-query boundary:

- `execute_stage2_query` accepted a jq expression whose `test()` input was an
  object, then failed with a low-level type error.
- `inspect_session_files` rejected a session directory with only `is a
  directory`, even though `get_session_directory` naturally returns directories
  and file lists for the same workflow.
- Query outcomes do not expose one uniform account of sessions considered,
  loaded, skipped, backend selected, fallback taken, and matches returned.
- Schema/runtime drift has repeatedly produced declared-but-ignored or
  executable-but-undeclared arguments (DIR-023, DIR-041, DIR-045, DIR-048).

These are correctness and discoverability problems. They should be resolved
before adding richer result-shaping conveniences.

## Decision Context

ADR-009 defines MCP as the supported query execution boundary. Stage 2 remains
an expert interface, but callers should not need source inspection to determine
the input value types or understand whether a query searched the intended
corpus.

## Scope

1. Add a bounded Stage 2 preflight over representative input records before
   full execution.
2. Turn common jq type failures into actionable diagnostics that identify the
   observed type and suggest a valid field path or coercion. Do not rewrite
   caller jq silently.
3. Make `inspect_session_files` safely accept provider-owned session
   directories, or return a structured correction pointing callers to the
   exact `get_session_directory(...).files` value. Preserve path sandboxing.
4. Define and emit a uniform query diagnostic envelope for applicable query
   tools, including:
   - provider/backend requested and actually used;
   - sessions/files considered and loaded;
   - skipped/unreadable counts with bounded warnings;
   - fallback/degraded mode;
   - match and returned-record counts.
5. Extend schema-to-runtime and documentation-recipe drift gates so special and
   pipeline dispatch paths are both covered.

## Non-Goals

- Do not replace jq or remove `execute_stage2_query`.
- Do not duplicate DIR-031 FTS implementation, DIR-034 cursor fetching, or
  DIR-004 response pagination.
- Do not make current-source Bash inspection part of meta-cc query diagnostics.
- Do not leak raw sensitive content, absolute paths beyond existing contracts,
  or unbounded per-file errors in diagnostics.

## Acceptance Criteria

- A Stage 2 query applying `test()` to an object fails before full-corpus
  execution with the observed type and at least one actionable correction.
- Valid Stage 2 jq behavior and result ordering remain unchanged.
- Passing a directory returned by `get_session_directory` to
  `inspect_session_files` either works safely or yields a structured correction
  containing the exact supported files workflow.
- Representative Claude, Codex, `provider=all`, fallback, and partially corrupt
  corpus tests assert the uniform diagnostics and bounded warnings.
- Runtime argument validation is tested before every dispatch path; a declared
  recipe or parameter that is not executable fails a deterministic repository
  gate.
- Current MCP reference and Stage 2 guide document the shipped diagnostic
  fields and type-preflight behavior.
- `make commit` passes.

## Dependencies

- ADR-009: Query Execution and Result Consumption Contract.
- Preserve the contracts delivered by DIR-018, DIR-023, DIR-031, DIR-039,
  DIR-041, DIR-045, and DIR-048.
