## Finding

Measured 2026-07-30: ~30 Codex e2e tests in `internal/mcp/executor` cost
0.6–1.2s each, and every one calls `setupCodexRolloutFixtureProject()` from
scratch — there is no shared fixture and no `TestMain`. The repeated fixture
construction (temp dir + rollout file materialization) is pure duplication and
contributes materially to the package's 34.2s `-short` wall time (74% of the
46.3s suite total).

Downstream cost is real: `make commit` ≈62s; the gate log since 2026-07-28
records 79 acceptance runs (≈82 min total wait; DIR-056 ran acceptance 9 times).
Cutting per-test fixture overhead is a safe, high-leverage win that complements
the parallelization work (DIR-082).

## Dependencies

None. Coordinating with DIR-082 (t.Parallel) is beneficial but not required;
either can land first.

## Scope

owner_repo: meta-cc

Test-only refactor of Codex fixture construction. Replace per-test
`setupCodexRolloutFixtureProject()` duplication with a package-level cached
fixture (via `TestMain`) or an `internal/testutil/` helper. Tests receive
read-only references or cheap copies; per-test isolation must be preserved —
no test may observe another's mutations.

## Touches

internal/mcp/executor/codex_*_test.go
internal/testutil/ (only if a shared helper moves there)

## Plan

1. Inventory the ~30 call sites of `setupCodexRolloutFixtureProject()` and
   classify which fixture variants they need.
2. Implement a shared, immutable base fixture: either built once in `TestMain`
   and handed out as read-only references, or via a testutil helper that
   cheap-copies only the parts tests mutate.
3. Migrate all call sites; keep the old helper until every site is converted,
   then remove or thin it.
4. Prove isolation: `go test -short -count=2 ./internal/mcp/executor/` must
   pass (catches cross-test state leakage).
5. Re-measure average per-test cost for the Codex e2e tests; record
   before/after in the commit message.

## Acceptance Criteria

- [ ] Average per-test cost of the ~30 Codex e2e tests ≤0.3s (down from 0.6–1.2s).
- [ ] All executor tests pass under `-short` and the full (non-short) path.
- [ ] No cross-test state leakage: `-count=2` run passes.
- [ ] No production (non-test) code changed.
