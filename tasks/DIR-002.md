## Finding

`quality_scan`'s `completion_rate` dimension always reports `0` (e.g., `0/4158` across
quay's entire project history). This is never correct for a live project. The metric
appears to measure closed sessions vs total tool calls, but the denominator or
classification is wrong.

Root cause identified in two-part data/schema mismatch:

1. **`ExtractToolCalls` does not normalize `Status`** (`internal/types/toolcall.go:80-84`):
   Real Claude Code JSONL uses `is_error: true/false` on `tool_result` blocks but does NOT
   include a `status` field. The code copies `result.Status` (which is `""` for real data)
   without inferring `"success"` from `IsError == false`. Every successful `ToolCall` ends
   up with `Status: ""`.

2. **`completion_rate` checks only `tc.Status == "success"`** (`internal/analyzer/quality_analysis.go:80`):
   Since all real tool calls have `Status: ""`, this check never matches. `successes` stays
   at `0`, and `completionScore = 0 / total = 0`.

The `error_rate` dimension does NOT have this problem (line 40 uses `tc.Status == "error" || tc.Error != ""` — the `Error` field IS populated for failed calls via `UnmarshalJSON` inference from `is_error: true`). The unit tests pass because they construct `ToolCall` structs directly with `Status: "success"`, bypassing `ExtractToolCalls` — the test fixture doesn't match real data.

## Proposal

Apply a two-part fix (defense in depth):

**Fix A (primary — normalize at the data layer):** In `ExtractToolCalls` (`internal/types/toolcall.go`), after copying `result.Status` and `result.Error`, infer `Status` from `IsError` when `Status` is empty:
- `IsError == true` → `Status = "error"`
- `IsError == false` → `Status = "success"`

This ensures ALL downstream consumers of `ToolCall.Status` get normalized values.

**Fix B (defensive — make completion_rate robust):** In `QualityScan` (`internal/analyzer/quality_analysis.go`), add a fallback check so completion_rate doesn't depend solely on exact string match:
- Count as success if `tc.Status == "success"` OR (`tc.Status == ""` AND `tc.Error == ""`)

This guards against edge cases where Status normalization is bypassed.

## Plan

### Phase 1: Fix data-layer Status normalization
- **File:** `internal/types/toolcall.go` (lines 80-84, in `ExtractToolCalls`)
- After setting `tc.Status = result.Status` and `tc.Error = result.Error`, add:
  ```go
  if tc.Status == "" {
      if result.IsError {
          tc.Status = "error"
      } else {
          tc.Status = "success"
      }
  }
  ```

