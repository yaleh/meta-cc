## Finding

`quality_scan`'s `completion_rate` dimension always reports `0` (e.g., `0/4158` across
quay's entire project history). This is never correct for a live project. The metric
appears to measure closed sessions vs total tool calls, but the denominator or
classification is wrong.

## Acceptance Criteria

- [ ] `completion_rate` reports a non-zero value for a project with completed sessions
- [ ] The metric definition is documented (what does "completion" mean?)
- [ ] If the metric cannot be fixed, remove it rather than reporting misleading 0

## Definition of Done

- [ ] `quality_scan` for quay project returns completion_rate > 0
- [ ] Metric semantics documented in tool description
