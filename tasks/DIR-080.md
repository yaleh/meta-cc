## Finding

Large historical meta-cc queries correctly spill to `file_ref`, but callers
then use Read/Bash/jq to discover nested paths such as
`.turns[].message.content`. The current file reference exposes only top-level
field names and a truncated serialization of the first record. That is
insufficient for heterogeneous or nested result shapes and makes callers guess
the query contract.

The product issue is not that Bash follows every historical query. Bash is
appropriate when inspecting current source after finding historical evidence.
The avoidable friction is Bash used to reverse-engineer meta-cc output structure
or to implement common projection/grouping that the query service can perform
safely.

## Decision Context

ADR-004 preserves hybrid inline/file-reference delivery. ADR-009 requires the
file-reference envelope to be self-describing enough for normal result
consumption while retaining Bash/jq as an advanced escape hatch.

## Scope

1. Add a versioned, typed nested result-shape description to `file_ref`
   metadata. Cover arrays, nullable/optional fields, heterogeneous variants,
   and provider provenance.
2. Include a bounded, redacted structured sample selected to illustrate the
   declared shape. Do not attach an unbounded or supposedly complete sample.
3. Generate jq recipes from the actual emitted result shape and validate those
   recipes against the sample/fixture in tests.
4. Add server-side field projection for applicable flat and grouped query
   results, with explicit validation of unknown/incompatible paths.
5. Provide compact grouped output for query surfaces where repeated
   session-level inspection is a demonstrated workflow. Re-measure before
   extending `group_by_session`; do not reimplement already shipped support.
6. Design an optional issue/task-ready evidence bundle containing bounded
   excerpts, stable provenance, query criteria, and completeness diagnostics.
   Keep this workflow feature separate from the base response envelope.

## Non-Goals

- Do not remove `file_ref`, force large results inline, or promise zero
  follow-up tool calls.
- Do not duplicate DIR-004 pagination or DIR-031/034 performance work.
- Do not expose full transcripts, secrets, or oversized tool output in samples
  or evidence bundles.
- Do not add progressive streaming or a new MCP transport contract in this
  task; that requires separate measurement and, if pursued, an ADR amendment.

## Acceptance Criteria

- A nested `file_ref` result exposes machine-readable paths and types sufficient
  to construct a valid jq query without reading source code or guessing shape.
- Generated jq recipes execute successfully against representative Claude,
  Codex, grouped, and heterogeneous fixtures.
- Samples are deterministically bounded and redacted, and tests cover sensitive
  and oversized fields.
- Server-side projection reduces result size and rejects unknown or
  shape-incompatible fields with an actionable error.
- Grouping changes, if any, are justified by recorded measurements and preserve
  existing ordering, pagination, context, and provider semantics.
- Evidence bundles include query criteria, provenance, completeness/fallback
  diagnostics, and bounded excerpts suitable for attaching to a task.
- Inline and `file_ref` modes continue to represent the same logical result.
- Current MCP documentation and examples describe the shipped contract.
- `make commit` passes.

## Dependencies

- ADR-009: Query Execution and Result Consumption Contract.
- DIR-079 diagnostic fields should be reused rather than creating a second
  completeness/fallback vocabulary.
