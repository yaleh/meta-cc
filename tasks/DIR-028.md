## Finding

The canonical model collapses a Codex turn into `UserText`, one concatenated `AssistantText`, and `ToolCalls`. Codex app-server and rollout history represent a turn as an ordered item stream: user messages, multiple agent commentary/final messages, command executions, file changes, MCP calls, web searches, plan updates, reasoning records, and status transitions. Flattening these records loses phase, status, ordering, item identity, and provider-specific detail, and makes reliable deduplication and future paginated history support difficult.

## Dependency

Depends on DIR-027 so the baseline parser has correct message reconciliation and production-shaped fixtures.

## Proposal

Extend `internal/conversation` with a canonical ordered `Item` representation while retaining backward-compatible projections for existing Claude-oriented MCP queries. A turn should preserve stable IDs, status, ordered items, usage, and raw provenance. Provider adapters populate the canonical model; the existing record normalization layer projects it into the legacy message/tool shape only at the compatibility boundary.

## Contract

- `Thread -> Turn -> Item` is the loss-minimizing internal representation.
- Item types cover user message, agent message, tool call/result, command execution, file change, web search, plan update, reasoning metadata, compaction, and unknown/raw events.
- Agent messages retain phase when available, including commentary and final output.
- Unknown item kinds remain round-trippable without exposing unbounded raw payloads by default.
- Existing `provider=claude` query output remains backward compatible.
- Existing Codex convenience queries continue to expose the current normalized message/tool schema unless a new item-oriented query is explicitly requested.

## Plan

1. Add canonical item and turn-status types with JSON round-trip tests.
2. Adapt Codex rollout parsing to emit ordered items and derive the old flattened fields only as a compatibility projection.
3. Adapt the Claude provider without rewriting its established parser pipeline.
4. Move normalization decisions out of provider parsing and into a dedicated projection layer.
5. Add differential tests proving old query contracts remain stable while item-level fidelity improves.

## Acceptance Criteria

- [ ] A Codex turn with multiple commentary/final messages preserves their order and phase.
- [ ] Tool call/result pairing retains item and turn identities.
- [ ] Command, file-change, web-search, plan, compaction, and unknown items are representable.
- [ ] Claude default query snapshots do not change unexpectedly.
- [ ] Codex legacy query projections contain no duplicate text and no reordered tools.

## Definition of Done

- [ ] Canonical model and both provider adapters have focused tests.
- [ ] Compatibility behavior and extension rules are documented.
- [ ] `make commit` passes.
