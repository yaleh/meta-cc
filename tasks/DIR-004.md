## Finding

Large query results (analyze_errors, session_content) always spill to `file_ref` mode,
requiring a second Read step to access the data. For example, `analyze_errors` over 3 days
produced a 346KB file_ref that required a separate read. This adds friction to every
non-trivial query — the agent must make two tool calls instead of one, and must know to
limit Read to avoid context overflow.

Root cause: `AdaptResponse` in `internal/mcp/response/adapter.go:12` writes all data to a
temp JSONL file when size exceeds `DefaultInlineThresholdBytes` (32KB, defined in
`output_mode.go:13`). The client receives a `{mode: "file_ref", file_ref: {path, ...}}`
metadata object and must separately read the temp file. There is no pagination — all results
are accumulated into a single `[]interface{}` in the pipeline.

Additionally, analysis tools (`analyze_errors`, `analyze_bugs`, `quality_scan`,
`get_work_patterns`, `get_timeline`, `get_tech_debt`) bypass the pipeline entirely
(they call `marshalResult` directly in `service.go`) and never support file_ref mode,
potentially producing enormous inline responses.

Pagination structs already exist in `internal/filter/pagination.go` (`PaginationConfig`,
`PaginationMetadata`, `ApplyPagination`) but are unused in the MCP query response pipeline.

## Proposal

Add `offset` and `page_size` parameters to all query tools via `StandardToolParameters`.
Wire them into the pipeline: after results are assembled but before `AdaptResponse`, apply
`ApplyPagination` slicing. Include `PaginationMetadata` (`total_records`, `returned_records`,
`offset`, `page_size`, `has_more`) in every response (both inline and file_ref modes).

This gives agents a deterministic pagination contract: request page_size ≤ N to stay under
the 32KB inline threshold, paginate with offset until `has_more: false`.

File_ref mode is preserved as fallback for very large single-record results.

## Plan

### Phase 1: Add pagination parameters to standard tool schema
- **File:** `internal/mcp/tools/tools.go` (line 17, `StandardToolParameters`)
- Add:
  ```go
  "offset": {Type: "number", Description: "0-based record offset for pagination. Default: 0."},
  "page_size": {Type: "number", Description: "Max records per page. 0 = no limit (all results). Default: 0."},
  ```

### Phase 2: Wire pagination into pipeline config and execution
- **File:** `internal/mcp/pipeline/pipeline.go`
- Add `Offset int` and `PageSize int` fields to `PipelineConfig` (line 23)
- In `BuildResponse` (line 46): after `parsedData` is assembled, if `PageSize > 0`, apply
  `filter.ApplyPagination` to slice the data; compute `filter.CalculateMetadata`
- Pass pagination metadata through to the response builders

- **File:** `internal/mcp/executor/executor.go` (line 34, `NewToolPipelineConfig`)
- Extract `offset` and `page_size` from args and set on `PipelineConfig`

### Phase 3: Include pagination metadata in all responses
- **File:** `internal/mcp/response/adapter.go`
- `AdaptResponse` (line 12): accept optional `*filter.PaginationMetadata`; include `pagination`
  key in the response map for both inline and file_ref modes
- `BuildInlineResponse` (line 40): add `pagination` field
- `BuildFileRefResponse` (line 50): add `pagination` field

### Phase 4: Route analysis tools through the pipeline
- **File:** `internal/analysis/service.go` — for tools that currently call `marshalResult`
  directly, add a path that feeds results through `BuildResponse`/`AdaptResponse` when size
  exceeds threshold
- **File:** `internal/mcp/executor/analysis_handlers.go` — update handlers to use
  pipeline-aware response building instead of raw `marshalResult`
- This ensures `analyze_errors`, `analyze_bugs`, `quality_scan`, `get_work_patterns`,
  `get_timeline`, `get_tech_debt` all support file_ref fallback and pagination

### Phase 5: Update tests
- **File:** `internal/mcp/pipeline/pipeline_test.go` — add pagination tests
- **File:** `internal/mcp/response/adapter_test.go` — verify pagination metadata in responses
- **File:** `cmd/mcp-server/` — update integration tests to verify `has_more` behavior
- Run `make commit` to validate
