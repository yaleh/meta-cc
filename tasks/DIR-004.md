## Finding

Large query results (analyze_errors, session_content) always spill to `file_ref` mode,
requiring a second Read step to access the data. For example, `analyze_errors` over 3 days
produced a 346KB file_ref that required a separate read. This adds friction to every
non-trivial query — the agent must make two tool calls instead of one, and must know to
limit Read to avoid context overflow.

## Proposal

Add streaming or paginated output mode so large results can be consumed incrementally
without the file_ref round-trip. Or add a `limit` + `offset` pattern to all file_ref
queries so agents can request manageable chunks.

## Acceptance Criteria

- [ ] At least one query type supports paginated/streaming output instead of file_ref
- [ ] Agent can consume results in chunks ≤25K tokens without manual offset/limit management
- [ ] Backward-compatible: file_ref mode preserved as fallback for very large results
