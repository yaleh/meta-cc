## Finding

Codex history is evolving beyond legacy rollout replay. Current sessions already contain `compacted`, `world_state`, context-compaction, turn-abort, and thread-setting events. Codex app-server exposes projection-backed paginated history, item/turn pagination, spawn lineage, archived sessions, and view modes where `summary` or `unloaded` records are placeholders rather than complete content. The existing parser treats most of this as opaque unknown data and has no explicit completeness model.

## Dependencies

Depends on DIR-029 for the official backend and DIR-031 so large/paginated histories can be queried without repeatedly loading full transcripts.

## Proposal

Extend the canonical/backend contracts with history completeness, compaction boundaries, archive state, thread lineage, and paginated retrieval. Stable app-server methods remain the default; experimental methods are capability-negotiated and optional, with raw/offline fallbacks where correctness can be established.

## Contract

- `full`, `summary`, `unloaded`, truncated, and unavailable histories are distinguishable in results.
- Placeholder records are never presented as complete turns.
- Compaction preserves visible replacement history and boundary metadata without duplicating superseded content.
- Archived sessions are discoverable only when requested.
- Parent/child/ancestor lineage is represented when available, with explicit unknown state when spawn metadata was suppressed.
- Turn failure, abort, session end, and live/ongoing state are modeled explicitly.
- Per-session and per-page failures produce bounded warnings and resumable cursors rather than whole-corpus loss.

## Plan

1. Add completeness, lifecycle, compaction, archive, and lineage fields to canonical metadata.
2. Parse current rollout markers and state DB spawn edges where present.
3. Capability-negotiate paginated app-server methods without making experimental APIs mandatory.
4. Prevent summary/unloaded projections from entering the full-content index.
5. Add multi-page, compaction, crash/abort, archive, and missing-lineage fixtures.
6. Add compatibility tests across legacy files, current files, app-server responses, and fallback behavior.

## Acceptance Criteria

- [ ] Partial history is labeled and never silently treated as complete.
- [ ] Compacted sessions do not duplicate replaced messages in content queries.
- [ ] Archived and active sessions obey explicit filters.
- [ ] Parent/child lineage queries work when metadata exists and report uncertainty when it does not.
- [ ] Page/session failures retain valid results and actionable continuation metadata.
- [ ] Legacy non-paginated sessions remain readable.

## Definition of Done

- [ ] Cross-version golden tests cover legacy, Codex 0.145-shaped, compacted, paginated, archived, and subagent histories.
- [ ] Experimental capability boundaries are documented and fail safely.
- [ ] `make commit` passes.
