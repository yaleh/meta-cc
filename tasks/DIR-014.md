## Finding

`gate_run(gate=vitest)` failed 2x in session `2a38491e` because `vitest` was not registered. This cascaded into `lifecycle_retreat` of DIR-001 from ready back to todo. `quay gate --list` confirms vitest absent. Tasks can reference unregistered gates in their acceptance command and only discover the gap at gate-run time.

## Proposal

Validate gate names at task_write time: if a task's acceptance command references a gate, verify it exists in the registered gates list. Reject writes that reference unregistered gates. Improve `gate_run` error to suggest available gates.

- [ ] `task_write` with unregistered gate in acceptance command is rejected with clear error
- [ ] `gate_run` with unregistered gate name includes available gates list in error
- [ ] Existing tasks can still reference registered gates (no regression)
