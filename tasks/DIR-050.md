# Codex rollout turns whose only content is a typed lifecycle item (`session_end`, `turn_aborted`, or a standalone `compaction` boundary) are silently dropped in their entirety by `turnBuilder.flush()`

## Finding

`internal/provider/codex/rollout.go`'s `turnBuilder.flush()` (lines 274-296) only appends the in-progress `b.current` Turn to `b.turns` when at least one of these is true:

```go
// internal/provider/codex/rollout.go:284
if b.current != nil && (b.current.UserText != "" || b.current.AssistantText != "" || len(b.current.ToolCalls) > 0 || hasUsage(b.current.TokenUsage) || len(b.current.Extensions) > 0) {
    ...
    b.turns = append(b.turns, *b.current)
}
b.current = nil
```

DIR-032 (commit `2f93b73`) added three new item kinds that are appended directly to `b.current.Items` but are **never** projected into `UserText`/`AssistantText`/`ToolCalls` by `projectLegacyFields()` (lines 240-272, which only handles `ItemKindUserMessage`, `ItemKindAgentMessage`, `ItemKindToolCall`, `ItemKindToolResult`):

- `turn_aborted` (line 433-441): sets `b.current.Status = conversation.TurnStatusAborted` but appends no Item at all.
- `session_end` (line 442-454): appends an `ItemKindSessionEnd` Item.
- `compacted`/`context_compacted` (lines 353, 420-432, via `appendCompactionItem`): appends an `ItemKindCompaction` Item.

If any of these events is the *only* content that ever entered the current turn (no user/assistant message, no tool call, no token usage delta, no still-unclassified/raw extension event), `flush()`'s condition at line 284 is false for every one of its five checks, so the turn is discarded wholesale — the Status, the ItemKindSessionEnd item, and the ItemKindCompaction item all vanish, and `len(turns)` doesn't even include an empty placeholder turn. This directly contradicts the stated purpose of DIR-032's promotion of these events out of raw passthrough ("a typed session/turn-lifecycle item ... rather than raw passthrough", `docs/reference/codex-history-model.md`) — the events are typed, but only reachable by callers if unrelated message content happens to coexist in the same turn.

using this fixture for the session_end case (a `task_started` opens turn `t1`, then a bare `session_end` — nothing else — before EOF):

```json
{"timestamp":"2026-06-14T06:00:00Z","type":"event_msg","payload":{"type":"task_started","turn_id":"t1"}}
{"timestamp":"2026-06-14T06:00:05Z","type":"session_end","payload":{"reason":"completed"}}
```

and analogously for `turn_aborted` (a turn opened by `task_started` then immediately aborted with no message/tool activity — a very plausible real scenario, e.g. the user hits Ctrl-C right after the model starts thinking, before any assistant text streams).

This matters because:
1. Existing tests (`TestLoadTurnsFromRollout0145TypedEventFamilies`, `TestLoadTurnsFromRolloutCompactionDoesNotDuplicateContent`) only exercise these events *interleaved with* real message content in the same turn, so they never hit this path — the gap has zero test coverage.
2. A session that ends right after being opened (no assistant response yet, e.g. an error or immediate disconnect) is a realistic real-world shape, and today it produces zero turns from `loadTurnsFromRollout` — the session looks like it has no history at all to any MCP caller (`query_session_content`, analysis tools, `query_sessions`'s turn-derived fields), rather than "one turn, aborted/ended, no content."
3. This silently defeats `docs/reference/codex-history-model.md`'s own stated turn/session lifecycle-status goal: a caller cannot rely on `TurnStatusAborted` or a typed `session_end`/`compaction` item being observable just because the underlying rollout recorded the event — it depends on unrelated content happening to share the turn.

## Proposal

Extend `flush()`'s retention condition (line 284) to also retain a turn that carries any lifecycle-signaling item or non-default status, e.g.:

```go
hasLifecycleSignal := b.current.Status != conversation.TurnStatusUnspecified
for _, it := range b.current.Items {
    if it.Kind == conversation.ItemKindSessionEnd || it.Kind == conversation.ItemKindCompaction {
        hasLifecycleSignal = true
        break
    }
}
if b.current != nil && (b.current.UserText != "" || b.current.AssistantText != "" || len(b.current.ToolCalls) > 0 || hasUsage(b.current.TokenUsage) || len(b.current.Extensions) > 0 || hasLifecycleSignal) {
```

Alternatively, retain whenever `len(b.current.Items) > 0` regardless of kind, which is simpler and covers any future item kind added to `Items` without another handler-specific carve-out.

## Acceptance Criteria

- [ ] A rollout ending in a bare `session_end` event (with a preceding `task_started` and no other turn content) produces exactly one Turn whose `Items` contains the typed `ItemKindSessionEnd` entry — not zero turns.
- [ ] A rollout ending in a bare `turn_aborted` event (with a preceding `task_started`, no message/tool activity) produces exactly one Turn with `Status == conversation.TurnStatusAborted`.
- [ ] A rollout containing a `compacted`/`context_compacted` event with no other content in that turn produces one Turn whose `Items` contains the typed `ItemKindCompaction` entry with its `CompactionBoundary`.
- [ ] Existing tests (`TestLoadTurnsFromRollout0145TypedEventFamilies`, `TestLoadTurnsFromRolloutCompactionDoesNotDuplicateContent`, `TestLoadTurnsFromRollout0145EventFamilies`) continue to pass unchanged.
- [ ] `go test ./internal/provider/codex/...` passes.
