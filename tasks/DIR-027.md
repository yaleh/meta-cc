## Finding

Live Codex CLI 0.145.0 rollout files record assistant text through both `event_msg.agent_message` and `response_item.message`. `internal/provider/codex/rollout.go` currently appends both representations, so `query_session_content(provider=codex, role=assistant)` returns every assistant segment twice. Existing synthetic fixtures exercise only one representation at a time and therefore miss the defect.

The live schema also contains event families absent from the current fixtures, including `world_state`, `compacted`, `tool_search_call`, `tool_search_output`, `thread_settings_applied`, `context_compacted`, `turn_aborted`, and `session_end`.

## Proposal

Define explicit source precedence for semantically duplicated Codex events and add sanitized, minimal fixtures derived from Codex 0.145 rollout shapes. Prefer the richer `response_item` representation for persisted user/assistant content and use `event_msg` as a fallback when no corresponding response item exists. Deduplication must be scoped to a turn, role, and source identity; do not globally remove repeated text because users and agents may legitimately repeat a message.

## Contract

- A logical assistant segment is emitted exactly once when both event representations exist.
- Event-only legacy sessions continue to produce user and assistant text.
- Tool calls, outputs, timestamps, turn IDs, and token usage remain unchanged.
- Fixtures contain no user secrets, repository content, credentials, or unbounded tool output.
- Unknown production events remain observable through typed records or explicit raw-event preservation; they are not silently discarded.

## Plan

1. Add a failing regression fixture containing paired `agent_message` and assistant `response_item.message` events from the same turn.
2. Implement source-aware message reconciliation in the Codex turn builder.
3. Add sanitized fixtures for the observed Codex 0.145 event families and schema-key variants.
4. Add end-to-end assertions through `providerrecords.Build` and `query_session_content`, not parser-only tests.
5. Document the precedence rule and the fixture-refresh procedure for future Codex CLI versions.
