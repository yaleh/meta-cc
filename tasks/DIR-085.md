## Finding

Measured 2026-07-30: `internal/version` takes 4.6s under `-short`, dominated by
the DIR-049 ldflags test, which spawns a `go build -ldflags` subprocess. A
compiler invocation inside the short path is disproportionate: this one package
contributes ~10% of the 46.3s suite wall time for a single assertion that only
needs to run on the full path.

Context: executor dominates at 34.2s (74%), but every package matters because
`make commit` ≈62s feeds the acceptance gate — since 2026-07-28, 79 gate runs
have accumulated ≈82 min of total wait (DIR-056 alone ran acceptance 9 times).
The ldflags guarantee itself must be preserved on the full `make push` / CI
path, where DIR-049's coverage promise lives.

## Dependencies

None.

## Scope

owner_repo: meta-cc

Test-only change in `internal/version/ldflags_test.go`: skip the subprocess
assertion under `-short`, keep it on the non-short path. Optionally cache a
build artifact across runs if that meaningfully helps the full path, but do not
weaken the assertion itself.

whatever board files lack them; in this worktree it touched
`tasks/AC118-00{1,2,3}.md`, which are not in this task's `## Touches`. Those
edits were reverted rather than committed, so the branch carries only
`internal/version/ldflags_test.go`. The fix mode of that gate exits 0 and is
idempotent, so a later run re-applies it harmlessly; the underlying board
condition is pre-existing on `develop` and unrelated to DIR-085.
