## Finding

(Original finding, 2026-07-25) Three consecutive `execute-milestone` runs returned `needs-human` with `it0-checks-failed` after promotion, wasting ~396K tokens: build/test viability was only checked during execution, not at the todo→ready boundary.

(Re-scoped 2026-07-30) The current architecture partially mitigates this: the loop-driver dispatches builds to subagents and a build failure routes to `needs-human` without touching main. But an early screen still saves a full subagent dispatch per unbuildable task. The todo→ready promotion path runs the workspace `dod` gate (`lifecycle_promote` → gate `dod`), and that gate's script chain is workspace-owned: `scripts/gates/it0-dod-check.sh` → `it0-dod-check.ts`, registered in `.quay/config.yml`. Extending THAT chain is meta-cc work; wiring a brand-new gate into quay's lifecycle code is not (out of scope, reported only).

## Resolution (landed aa72ee6, 2026-07-30)

Delivered: new `scripts/gates/build-feasibility-check.sh` (fail-closed `go build ./...` screen, cwd-independent, exit 1 broken / exit 2 no toolchain), prepended into `scripts/gates/it0-dod-check.sh` before TS delegation, and registered as the `fixed` gate `build-feasibility` in `.quay/config.yml` (timeoutMs 180000). Standalone-tested broken-build and clean cases in a scratch copy; real gate invocations recorded in `.quay/gate-events.jsonl`.

**Key structural finding (verified independently by the adversarial audit):** quay's `resolveGate` (packages/quay/src/gate/registry.ts:117-120) checks the built-in `gateRegistry` BEFORE workspace gates, and a built-in `dod` exists; `runPromote` hardcodes `gate: "dod"`. The workspace it0 `dod` gate is therefore SHADOWED and unreachable on the todo→ready path; `dodArgs` is neither required nor consulted during promotion. The literal first AC as originally written is unachievable workspace-side — wiring the screen into promotion itself requires a quay change (workspace-gate precedence or a promote-time gate list), which per the Quay Workspace Boundary is REPORTED ONLY, not implemented here.
