## Finding

Worktree subagents build in `/tmp/meta-cc-worktrees/<id>`. Full `make commit` runs ~62s each; 79 acceptance runs since 2026-07-28 cost ~82 min of wait, with retries (DIR-056 ×9, DIR-053 ×5, DIR-058 ×4). If each worktree builds with a cold Go cache, every first build/test pays full compilation cost on top of that. Whether GOCACHE/GOMODCACHE/GOPATH are shared across worktrees — so Go's content-addressed build and test caches stay warm — is unverified. DIR-008 proposed an environment-validation gate for worktree subagents but was closed-obsolete: its gate script was never checked into `scripts/` (invocation moved to the loop-driver deps-ready step, which lives in the quay skill repo). The repo-scoped artifact this task can own is the cache-sharing verification and documentation.

## Dependencies

None. Complements DIR-090 (scoped fail-fast checks reduce per-retry cost; warm caches reduce per-run cost).

## Proposal

**What/Why**: The caches are in fact shared by default — but nothing verifies or pins it, which is the gap. Measured 2026-07-30: `go env GOCACHE` → `/home/yale/.cache/go-build`, `go env GOMODCACHE` → `/home/yale/go/pkg/mod`, `GOFLAGS` empty, and the values are identical from an unrelated cwd (`/tmp`), because both defaults hang off `$HOME`. Any worktree under `/tmp/meta-cc-worktrees/<id>` therefore shares one content-addressed build/test cache *iff* the dispatched subagent inherits HOME and nothing overrides the cache vars. Nothing today asserts that precondition: the Makefile's only environment export is PATH hardening (Makefile:10), and no target sets GOFLAGS/GOCACHE/GOMODCACHE — `test:` runs `$(GOTEST) -short -v ./...` bare (Makefile:526-528), `build:` runs `$(GOBUILD)` bare (Makefile:360-363), both reached through `commit:` (Makefile:321), the acceptance command for this and most tasks. `scripts/gates/build-feasibility-check.sh:46` runs a bare `go build ./...` trusting the ambient env, and `.quay/config.yml`'s loop (`execution: dispatched`, `concurrency: 4`) passes only `QUAY_NATIVE_*` provider env — no cache vars — while its build-feasibility gate comment already acknowledges that "Cold `go build ./...` can exceed the 60s default timeout" (hence `timeoutMs: 180000`). The override risk is not hypothetical: this repo itself points GOCACHE at a repo-local `.gocache` in `scripts/ci/capture-cli-metrics.sh:9-31` (and `capture-mcp-metrics.sh`), proving the variable gets rewritten in real workflows. Repo precedent for a fail-closed environment regression check exists in `check-path-independence` (Makefile:268-283), which spawns `env -i HOME="$$HOME" PATH=/usr/bin:/bin make` — notably preserving HOME, the exact variable the cache defaults depend on. So the honest shape of this task is verification + enforcement/pinning of an already-true default, not construction of cache sharing from scratch.

**Approach**:

1. Audit and measure: capture `go env GOCACHE GOMODCACHE GOFLAGS GOPATH` plus `HOME` from the repo root, from a scratch `/tmp/meta-cc-worktrees`-style cwd, and — when one is available — from an actually dispatched worktree subagent run; attach the measured values as task evidence.
2. Add `scripts/checks/check-worktree-cache-env.sh`: report the resolved GOCACHE/GOMODCACHE values; PASS when both resolve to shared, non-worktree-local paths under `$HOME`; FAIL fail-closed on per-worktree isolation (a cache path inside the worktree), an unset-HOME/empty-derived default, or explicit GOCACHE/GOMODCACHE overrides pointing into a worktree; WARN (non-fatal) when the shared cache directory is empty/cold. Follow the established check-script conventions — executable, `set -u`, SCRIPT_DIR-relative workspace resolution as in `scripts/gates/build-feasibility-check.sh:33-34` — so it passes the shellcheck validation that `scripts/checks/check-scripts.sh` runs over every script.
3. Prove warmth: build one worktree (`time go build ./...`), then build a second worktree for another task and attach evidence of cache hits — a before/after cold-vs-warm timing comparison, or a `go build -x` trace showing cached artifacts.
4. Add a comment-only block to the `.quay/config.yml` loop section recording the expected shared-cache environment for dispatched worktree builds (GOCACHE=`$HOME/.cache/go-build`, GOMODCACHE=`$HOME/go/pkg/mod`, no GOFLAGS override) and naming the new check script; no YAML key or value changes.
5. Document the expected worktree environment, how to run the check, and the failure modes it detects in `docs/guides/plugin-development.md`.

**Out of scope**:

- quay loop-driver / skill code — it lives in a different repository (Quay Workspace Boundary); DIR-008's invocation now sits in the loop-driver deps-ready step there, and this task is report-only on that side.
- Wiring the check into `make commit` / `check-essential` (Makefile:58, 321) or registering it as a `.quay/config.yml` gate — this task ships comments there, not a gate entry or Makefile target.
- Build-flag changes, test-target verbosity (DIR-087), or fail-fast check scoping (DIR-090).

**Risks**:

- Enforcement ceiling: a repo-local check plus config comments can document and detect, but cannot force what the dispatcher (another repo) does with the subagent environment; mitigated by a fail-closed check and by explicitly documenting the loop-driver deps-ready step as the true enforcement point.
- Timing-evidence volatility under `concurrency: 4` (disk/CPU contention can mask cache benefits); mitigated by accepting a `go build -x` cache-hit trace as alternative evidence.
- New script must survive `scripts/checks/check-scripts.sh`'s shellcheck pass (per its header, shell-script errors are ~30% of CI failures); mitigated by copying the `build-feasibility-check.sh` structure and running `make check-scripts` before `make commit`.
