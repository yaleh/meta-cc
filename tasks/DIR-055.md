# get_tech_debt source scan is dominated by self-referential false positives, counts prose as debt, and double-counts transcript∩source overlap

## Finding

Measured evidence — `get_tech_debt({scope:"project", source_dir:"/home/yale/work/meta-cc/internal", stats_first:true})`
run in session `16c504aa-6681-40b0-bfce-4f25f4dce679` on 2026-07-28 reported
markers `TODO:59, FIXME:40, HACK:38, XXX:29` (166 total) with hotspot ranking:

| hotspot file | count | what it actually is |
|---|---|---|
| `internal/analyzer/tech_debt_test.go` | 36 | test **fixtures** for the scanner itself |
| `tasks/DIR-003.md` | 22 | task **prose** ("scan for TODO/FIXME/HACK/XXX markers") |
| `internal/analyzer/tech_debt.go` | 20 | the scanner's own regex literal + doc comments |
| `internal/mcp/tools/tools.go` | 16 | MCP tool **description strings** ("Detect TODO/FIXME/HACK/XXX markers...") |
| `/tmp/claude-1000/.../check-no-scanner-recurring-violation.md` | 4 | a scratchpad markdown file read during a session |

The top 4 hotspots (94 markers) are all false positives; the only genuine debt marker
in non-test `internal/` source is `internal/types/constants.go:7`
(`// TODO(post-stabilization): remove LargeLineWarnBytes...`), and even
`internal/parser/bounded_reader.go:25` (count 1) is prose *mentioning* "TODO markers"
inside a comment, not a marker. The tool reports the debt-detector's own
implementation as the project's worst debtor.

Three distinct root causes, all in `internal/analyzer/tech_debt.go`:

1. **Self-match**: `markerPattern = regexp.MustCompile(`\b(TODO|FIXME|HACK|XXX)\b`)`
   (`tech_debt.go:14`) matches its own definition, every doc comment describing the
   feature (`tech_debt.go:60,132`), the tool schema descriptions in
   `internal/mcp/tools/tools.go:385,392`, and the test fixtures in
   `tech_debt_test.go`. Nothing distinguishes a marker from a mention.
2. **Prose scanned as code**: `knownCodeExtensions` (`tech_debt.go:49-53`) includes
   `.md` and `.json`, so documentation and task files are counted as source debt in
   `ScanSourceDir` mode (`tech_debt.go:152-155`).
3. **Double-count on merge + no provenance**: `internal/analysis/service.go:457-458`
   unconditionally merges the session-transcript scan (`GetTechDebt`, which counts
   markers inside Read/Edit/Write/Bash tool *output* text, `tech_debt.go:67-82`) with
   the `ScanSourceDir` result via `MergeTechDebtResults` (`tech_debt.go:235-283`),
   whose docstring says it dedups hotspot files "by path (summing their counts)"
   (`tech_debt.go:246-251`). A file with markers that was both Read during a session
   and source-scanned is counted twice. The merged hotspot list also carries no
   provenance — the measured output mixes `/tmp/...` scratchpad files and
   `tasks/DIR-003.md` (transcript-derived, *outside* the requested `source_dir`)
   with `internal/` files (source-derived) in one ranking, so a caller cannot tell
   which bucket an entry came from.

Additionally, the identical build-markers+build-hotspots+`sort.Slice` block is
copy-pasted three times (`tech_debt.go:84-103`, `202-221`, `253-270`) — a
crystallization opportunity that is part of the same fix surface.

Recurrence: fires on every `get_tech_debt(source_dir=...)` invocation in any repo that
contains docs/tests mentioning the marker words — i.e. essentially every real repo,
and maximally so in meta-cc itself (pure dogfood failure). Not a duplicate: DIR-003
(done) added source scanning; DIR-022 (todo) covers only the swallowed `ScanSourceDir`
error; no task addresses false positives, `.md` inclusion, or merge double-counting.

## Proposal

1. **Comment-context matching**: count a marker only when it appears in a comment
   context for the file's language (Go `//`/`/* */`, Python `#`, JS/TS `//`, shell `#`,
   YAML `#`, etc.), with a conservative fallback of line-start/after-whitespace marker
   for languages without cheap detection. This eliminates self-matches in string
   literals, regexes, tool descriptions, and test fixtures (which use quoted strings).
2. **Drop `.md`/`.json` from `knownCodeExtensions`** for source-dir mode (or move them
   to a separate `docs_markers` bucket that never enters the code-debt hotspot ranking).
3. **Merge by max, not sum, per path**, and add a `provenance` field
   (`"session"|"source"|"both"`) to `FileDebt` so merged output is auditable; transcript
   hits outside the requested `source_dir` must be distinguishable from source hits.
4. **Crystallize** the triplicated build+sort block into one
   `buildTechDebtResult(labelCounts, fileCounts map[string]int, openIssues int, source DataSource) *TechDebtResult`
   helper used by `GetTechDebt`, `ScanSourceDir`, and `MergeTechDebtResults`.
