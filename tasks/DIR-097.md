## Finding

Dogfooding session (2026-07-30): analyzing this project's own 2-day task-execution history with meta-cc's MCP tools, a consumer called `query_session_signals(type="errors")` and received raw user-role JSONL records. `toolUseResult` is a string in some records and an object in others; the actual error text is nested inside `message.content[].content`. The consumer's first jq extraction attempts returned nothing because the shape is undocumented and irregular — the raw JSONL had to be inspected by hand to extract error texts.

CLAUDE.md's docs describe role=tool "block fields", but the errors signal's actual shape differs from what a consumer builds from that guidance. This is a projection gap: the signal tool passes raw record variance through instead of normalizing to a contract the docs can promise.

## Resolution (2026-09-14)

Supersedes the earlier `## Needs-Human` entry (3 failed fix attempts). The blocker there was the projection itself; it is now implemented and verified.

**What landed.** `internal/query/signal_errors.go` projects each failing `tool_result` onto the five fields. The tool name is recovered by correlating the failing block with the assistant `tool_use` that issued it — a single unbounded jq pass (`ErrorSignalJoinJQ`) emitting both record kinds, joined in Go, because the jq pipeline runs one record at a time with no cross-record join (the same constraint `handleQueryTools`' status filter works around). `error_text` follows the parser's precedence (block `error`, then block `content`, then record `toolUseResult`), which is what makes the category agree with `analyze_errors`; an unrecognized `toolUseResult` object yields `""` rather than a serialization of the whole value, keeping the projection bounded (an `Edit` result carries a whole file body). `raw=true` restores the pre-DIR-097 record. `internal/mcp/tools/tools.go` declares the new `raw` parameter (added to `## Touches` here — the original declaration omitted it).

**AC verification.**

1. Run against this project's real session corpus (44 failing calls): every one of the 44 projected records carried all five fields, all present and non-empty strings, at the top level — not merely reachable through a nested path. Fixture tests cover the corpus's string-variant record verbatim plus the object-variant shape.
2. On the same corpus, `query_session_signals(type="errors")` and `analyze_errors` produced identical totals and identical label→count maps (`bash_exit_code` 32, `uncategorized` 12). Both call `analyzer.ClassifyErrorType`; this is structural, not coincidental.
3. `docs/guides/mcp-query-tools.md` gained the five-field table, the category vocabulary, the `raw` parameter, and jq examples; `docs/guides/two-stage-query-guide.md` gained Pattern 4. The documented examples are executed through the real tool by the executor tests, so they cannot rot — this caught one: the histogram recipe needs a trailing `.[]`, because the pipeline turns each jq output *line* into one entry, so without it the whole histogram arrived as a single array-valued entry.
4. `jq_filter` composition is covered end-to-end over the projected records, including a select on `.category` (a field the raw record never had).
5. `raw=true` returns the untouched record — `type: "user"`, `toolUseResult`, camelCase `sessionId`, and none of the projection-only fields.

The fourth DoD item (landed on main) is the worker-driver's fan-in step, not this worker's; it is left unchecked here and is satisfied by the fan-in that follows this commit.
