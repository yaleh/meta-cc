## Finding

Measured 2026-07-30: `go test -short -count=1 ./...` wall time is 46.3s and the
`internal/mcp/executor` package alone accounts for 34.2s — 74% of the suite.
The package contains 120 test functions across 21 test files and ZERO of them
call `t.Parallel()`, so every test runs serially on one core while doing mostly
I/O (temp-dir fixture setup, file writes, exec plumbing).

This serial wall time feeds directly into `make commit` (≈62s measured) and the
acceptance gate: since 2026-07-28 the gate log records 79 acceptance runs
(≈82 min of total wait), with DIR-056 alone re-running acceptance 9 times.
Parallelizing this package is the single highest-leverage reduction available.

## Dependencies

None.

## Scope

owner_repo: meta-cc

Test-only change inside `internal/mcp/executor/`. No production code is
modified. Fixtures are believed to be per-test temp dirs; the plan verifies
that assumption before enabling parallelism. The full-path (non-short) suite
and `make push` must remain green.

## Touches

- tasks/DIR-082.md

## Plan

1. Audit the 21 test files for shared mutable state: package-level vars, shared
   fixture dirs, global registries. Verify that fixtures are per-test temp dirs.
2. Add `t.Parallel()` to top-level test functions that are proven independent.
3. Parallelize table-driven subtests (`tc := tc; t.Parallel()`) where cases do
   not share mutable state.
4. Run `go test -race -short -count=1 ./internal/mcp/executor/` and fix any
   reported races (expected: none, if fixtures are truly per-test).
5. Re-measure `-short` wall time and record before/after in the commit message.

### 2026-09-17 — fan-in `ff` 根因：worktree 与 driver root 分属两个 clone（结构缺陷，非本任务代码缺陷）

`step=ff` 判词：`suite_head=86dbe26342a75866ff43120b7fae5e3cbbd09726 is NOT an
ancestor of 待 ff tip=54836b1747af2bf8539ad08b45906256ba85ead3`。

定位（读 `worker-driver.js` 的 `suiteCertGate()`）：

```js
const suiteTip = git(root, "rev-parse", `refs/heads/task/${args.task}`).stdout.trim();
```

`root` 是 driver 的主检出，`args.worktree` 只用于跑 suite。两者指向：

| 角色 | 路径 | `refs/heads/task/DIR-082` |
| --- | --- | --- |
| root（driver `--root`，runId `wk-prod-anchor`） | `/home/yale/quay-verify-upgrade-609dd467-root`（clone A，新 quay） | `54836b1`（陈旧值） |
| worktree | `/home/yale/work/meta-cc/.worktrees/DIR-082`（**clone B**，老 quay 0.7.0-dev） | suite 跑在 `86dbe26`，现为 `3371b1d` |

- `<worktree>/.git` 内容为 `gitdir: /home/yale/work/meta-cc/.git/worktrees/DIR-082`
  ⇒ 该 worktree 属于 clone B。clone A 内另有一条**同路径的陈旧 worktree 注册**
  （`.git/worktrees/DIR-082/`，mtime 2026-09-14），其 `HEAD` 为
  `ref: refs/heads/task/DIR-082`，而 clone A 的该 ref 停在 `54836b1`（clone B 上
  分支创建时的基点；在 clone A 里它恰是 develop 的祖先 ⇒ 即派发时报告的「0 commits」）。
- clone A 内**不存在** `86dbe26`（`git -C <cloneA> cat-file -t 86dbe26` →
  `fatal: could not get object info`）。故无论 socket 何时跑，`suite_head` 都不可能
  是该 ref 的祖先 ⇒ 证书闸结构性不可满足。
- 同一轮 fan-in 中其余各步（`merge-develop` / `anti-drift` / `typecheck` /
  `ac-precheck` / suite）**全部走 worktree ⇒ 全部 `ok:true`**，只有按 `root` 取 ref
  的 `ff` 为红。对照：同轮 ac239 的 fan-in `ff` `exit 0`（其 worktree 在 clone A 内）。

⇒ 与 AC / `## Touches` / 代码面无关（AC 4/4、anti-drift OK、suite 绿、scoped 门绿），
而是 **worktree 与 driver root 分属两个 clone** 的 workspace 结构缺陷：worktree 侧的
