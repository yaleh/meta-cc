## Finding

Measured 2026-07-30: `go test -short -count=1 ./...` wall time is 46.3s and the
`internal/mcp/executor` package alone accounts for 34.2s — 74% of the suite.
The package contains 120 test functions across 21 test files and ZERO of them
call `t.Parallel()`, so every test runs serially on one core while doing mostly
I/O (temp-dir fixture setup, file writes, exec plumbing).

This serial wall time feeds directly into `make commit` (≈62s measured) and the
acceptance gate: since 2026-07-28 the gate log records 79 acceptance runs
(≈82 min of total wait), with DIR-056 alone re-running acceptance 9 times.
Parallelizing this package is the single highest-leverage reduction available.

## Plan

1. Audit the 21 test files for shared mutable state: package-level vars, shared
   fixture dirs, global registries. Verify that fixtures are per-test temp dirs.
2. Add `t.Parallel()` to top-level test functions that are proven independent.
3. Parallelize table-driven subtests (`tc := tc; t.Parallel()`) where cases do
   not share mutable state.
4. Run `go test -race -short -count=1 ./internal/mcp/executor/` and fix any
   reported races (expected: none, if fixtures are truly per-test).
5. Re-measure `-short` wall time and record before/after in the commit message.

## Evidence

`t.Parallel()` added to 64 call sites across 8 files in `internal/mcp/executor/`
(54 top-level tests plus table-driven subtests), restricted to tests proven free
of process-global state: no `t.Setenv`/`t.Chdir` directly or via a fixture
helper, no mutation of the package-level registries or the `newCodexProvider`
seam, and no shared fixture dir — every fixture is a `t.TempDir()`.

The 68 tests left serial are a hard constraint, not a choice: `t.Parallel` panics
with `test using t.Setenv or t.Chdir can not use t.Parallel`, and those tests are
exactly the ones pinning `META_CC_PROJECTS_ROOT` / `META_CC_CODEX_ROOT` /
`META_CC_CODEX_BACKEND` / `HOME` / `CODEX_HOME`. The two registry writers
(`TestRegisterHandler_AddsToRegistry`, `TestRegisterQueryHandler_AddsToRegistry`)
also stay serial because they mutate the package-level maps — verified still
serial in `registry_test.go`.
