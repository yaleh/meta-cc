# analyze_errors classifier never matches Claude Code's "Exit code N" format — 72% of errors land in "uncategorized", timeouts mislabeled "connection_error"

## Finding

`ClassifyErrorType` (DIR-001, done) classifies Bash errors with the regex
`reExitStatus = regexp.MustCompile("(?i)exit status \\d+")` at
`internal/analyzer/errors.go:12`, applied at `errors.go:61-63` and wired into
`AnalyzeErrors` at `internal/analyzer/errors_analysis.go:88` and `:188`.

But Claude Code's Bash tool does not emit Go's `exit status N` string — it emits
`Exit code N` as the first line of every failed Bash call. The classifier's rule #2
therefore never fires on real Claude Code data.

Measured evidence — `analyze_errors({scope: "project", stats_first: true})` run in
session `16c504aa-6681-40b0-bfce-4f25f4dce679` on 2026-07-28
(time_range 2026-07-25T15:52:46Z → 2026-07-28T16:56:14Z, total_errors 29):

- `by_type` breakdown: `uncategorized: 21`, `file_not_found: 4`, `connection_error: 2`,
  `command_not_found: 1`, `resource_not_found: 1`. **`bash_exit_code: 0`** — not a single
  error received the label that exists specifically for shell failures, even though all
  21 Bash errors begin with `Exit code N` (e.g. `"Exit code 3\ngolangci-lint has version
  2.0.0-..."`, `"Exit code 2\nBuilding meta-cc-mcp v3.5.1-9-g2f93b73-dirty..."`).
  21/29 = 72% of all errors fall through to the `uncategorized` fallback (`errors.go:88`).
- Two false-positive `connection_error` labels from the loose `timeout|network`
  alternation in `reConnectionError` (`errors.go:16`):
  1. `"Exit code 143\nCommand timed out after 3m 0s\n[WARNING] Unstaged files detected..."`
     — a local pre-commit hook timeout, not a connection error.
  2. `"Exit code 1\n--- config.yml ---\n# .quay/config.yml — unified per-workspace
     config (DIR-050)..."` — a config dump whose YAML comment text contains
     `timeoutMs` ("optional per-gate cwd / timeoutMs overrides"), matched incidentally.
- The regression test only covers the wrong format: `internal/analyzer/errors_test.go:111-113`
  asserts `bash_exit_code` for fixtures `"exit status 1"`, `"exit status 127"`,
  `"exit status 0"` — Go `os/exec` strings, never the Claude Code harness format.
  DIR-001's proposal row 2 likewise specified only `/exit status \d+/`.

Recurrence pattern: this fires on **every** `analyze_errors` run against Claude Code
history (every Bash failure in this project is `Exit code N`). The history-mining
routine itself relies on `analyze_errors`/`analyze_bugs` to surface recurring defects,
so the misclassification degrades the project's own defect-detection loop:
`analyze_bugs` on the same window produced 19 signatures with no type labels and could
not group the 21 shell failures meaningfully (e.g. the recurring
`/usr/bin/python3: No module named pre_commit` failure appears only as opaque
signature `d6e9126e6892fece`, fix_count 2).

Not a duplicate: DIR-001 (done) introduced the labels; no task (DIR-001..053) covers
the format mismatch or the timeout false positives.

## Proposal

1. Fix the exit-code rule: change `reExitStatus` to `(?i)(exit status|exit code) \d+`
   (or add a dedicated first-class rule for `^Exit code \d+`, the Claude Code harness
   format).
2. Add a `command_timeout` label (`(?i)timed out|timeout after|ETIMEDOUT|deadline
   exceeded|exit code 143|exit status 143`) checked **before** `connection_error`, and
   narrow `reConnectionError` to genuine network signals
   (`connection refused|connection reset|ECONNREFUSED|ECONNRESET|network unreachable|dial tcp`)
   so incidental body text like `timeoutMs` cannot trigger it.
3. Extend `errors_test.go` with fixtures captured verbatim from real Claude Code
   transcripts (`"Exit code 143\nCommand timed out after 3m 0s..."`,
   `"Exit code 2\ncp: cannot create regular file ...: Text file busy"`,
   `"Exit code 1\n/usr/bin/python3: No module named pre_commit"`), including a
   negative test that a body merely mentioning `timeoutMs` does not classify as
   timeout/connection.
4. Add a golden-corpus coverage assertion: record the current project's measured error
   corpus (or a committed fixture corpus of real transcript errors) and assert
   `uncategorized` share < 25% — a standing gate that the taxonomy keeps pace with the
   harness's actual output formats (this is the missing test gate: DIR-001 was
   validated against synthetic Go-style strings instead of real harness output).
