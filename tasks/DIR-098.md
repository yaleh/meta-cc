## Finding

Dogfooding session (2026-07-30): a corrupt session file (`8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl`, "no Claude entries" — empty/truncated) sat undetected in the project session directory until it hard-crashed `query_sessions` (twice) on 2026-07-30. `get_session_directory` and `inspect_session_files` do not surface empty/unparseable files as data — the failure stayed a surprise instead of being discoverable before any query ran.

Structural root cause: DIR-018 (done) fixed skip-and-report tolerance in the analysis `loadData` path, but that behavior was lost/not propagated when DIR-032/DIR-034 rewrote and re-wired the ListSessions path behind `query_sessions`. The discovery tools enumerate files without reporting their health, so consumers keep learning about corruption at crash time.

## Dependencies

Complements DIR-094 (sibling task, tolerance contract).

## Scope

owner_repo: meta-cc

Make file health visible as structured data in the two discovery tools, so malformed files are discoverable before they crash a downstream query. Parse errors become data, never exceptions. Healthy-corpus output must remain unchanged.

## Touches

- `internal/mcp/executor/` (session-directory and inspect handlers)
- `internal/provider/` (health probes)
- tests

## Plan

1. Compute per-file health `{entries, parseable, empty, bytes, error?}` in a shared probe in `internal/provider/`.
2. `get_session_directory`: add a `malformed_files` aggregate (list of `{file, reason}`) to the response, empty for a healthy corpus.
3. `inspect_session_files`: report parse errors per file as structured fields instead of letting them propagate as crashes.
4. Add tests: an empty/truncated file is named as malformed with a reason; a healthy corpus produces an empty `malformed_files` list and output otherwise identical to before.

## Acceptance Criteria

- [ ] On this machine's project corpus, both tools name the 8eda8f4e-style empty file as malformed WITH a reason string.
- [ ] A healthy corpus produces an empty `malformed_files` list and otherwise unchanged output.
- [ ] The finding is discoverable WITHOUT running `query_sessions`.
- [ ] `inspect_session_files` returns structured parse-error data for a bad file instead of erroring.

## DoD
