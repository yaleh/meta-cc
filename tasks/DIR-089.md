## Finding

Measured 2026-07-30: `make commit` = check-essential + check-no-scanner + test ≈ 62s measured (budget says <60s). `check-essential` includes `check-docs` (the DIR-078 documentation contract gate), which runs `go test ./internal/release/...` — and the commit target's full `test` run re-tests that same package. internal/release is thus exercised twice per commit. Context: 33/36 recent tasks use `make commit` as acceptance, so the duplication compounds across 79 gate runs in 2 days (≈82 min total).

## Dependencies

Preserves the DIR-078 documentation contract gate; it must not be weakened on the commit path.

## Scope

Measure the actual cost of the double run (cache hit vs cold). Either reorder so the second run provably reuses Go's test cache, or fold check-docs into the test invocation with a documentation-constraint run marker — WITHOUT weakening the DIR-078 gate on the commit path. Attach measurement evidence to the task.

## Plan

1. Cold-cache timing: `go clean -testcache`, then `make commit`, recording per-invocation timings for the internal/release package (both occurrences).
2. Warm-cache timing: repeat the run and record whether the second occurrence is a cache hit.
3. Choose a strategy from the measurements: reorder for provable cache reuse, or fold check-docs into the test invocation with a run marker.
4. Implement, and add a negative test proving the DIR-078 gate still blocks a contract violation on the commit path.
5. Re-measure `make commit` cold and warm; attach the evidence to the task.
