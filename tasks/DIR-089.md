## Finding

Measured 2026-07-30: `make commit` = check-essential + check-no-scanner + test ≈ 62s measured (budget says <60s). `check-essential` includes `check-docs` (the DIR-078 documentation contract gate), which runs `go test ./internal/release/...` — and the commit target's full `test` run re-tests that same package. internal/release is thus exercised twice per commit. Context: 33/36 recent tasks use `make commit` as acceptance, so the duplication compounds across 79 gate runs in 2 days (≈82 min total).

## Dependencies

Preserves the DIR-078 documentation contract gate; it must not be weakened on the commit path.

## Scope

Measure the actual cost of the double run (cache hit vs cold). Either reorder so the second run provably reuses Go's test cache, or fold check-docs into the test invocation with a documentation-constraint run marker — WITHOUT weakening the DIR-078 gate on the commit path. Attach measurement evidence to the task.

## Measurement (2026-09-17) — read before crediting AC-1

Worktree `/home/yale/quay-verify-upgrade-609dd467-root-worktrees/DIR-089` (branch
`task/DIR-089`), Go 1.24.9, 4 cores, load average ~4.7 for the whole session
(other agents' worktrees run on the same box). "Cold" is the Plan's §1
definition: `go clean -testcache`.

**The double run is real. Its cost is ~0.06s, not ~2s.** internal/release is an
offline file scanner — three test files, no `testing.Short()` gating, no
network/subprocess — and `go test` reports 0.047–0.070s per execution. Thirty
seconds of duplication across 79 gate runs was never in this package; the
finding's 82 min is the *total* gate time, not the duplicated slice. The
structural defect was real (two executions per commit); the wall-clock premise
was not.

Cold, 3 reps per arm, guard test disabled in the BEFORE arm so the pre-change
Makefile is measurable at all (it is compiled into the suite it measures):

| arm | occurrence 1 (check-docs) | occurrence 2 (`test`) | `make commit` wall |
|---|---|---|---|
| BEFORE (`$(GOTEST) ./internal/release/...`) | 0.048s executed | 0.070s executed | 10.74s |
| BEFORE | 0.048s executed | 0.059s executed | 13.40s |
| BEFORE | 0.049s executed | 0.071s executed | 8.70s |
| AFTER (`$(GOTEST) -short ./internal/release/...`) | 0.058s executed | (cached) | 13.57s |
| AFTER | 0.047s executed | (cached) | 11.17s |
| AFTER | 0.049s executed | (cached) | 8.52s |

Warm (no clean), AFTER: 3.68s / 3.88s, **both** occurrences `(cached)`.

Executions per cold `make commit`: **2 → 1**. The wall-time delta between arms
is inside the noise band — the reclaimed work is 0.06s, and the 8.5–13.6s spread
within each arm is contention. AC-1 is ticked on the execution count, which is
unambiguous; the timing evidence is offered as the cache-reuse proof the AC's
parenthetical asks for, not as a speedup claim.

**Build-cache-cold** (fresh `GOCACHE` per run, one sample each, same session):
BEFORE 60.94s, AFTER 49.62s. So `make commit` lands ≤55s under the strict
reading too — but that 11s gap is *not* this change's effect. `-short` is a
runtime flag, so the compile graph is byte-identical across the two arms; the
only delta this change can produce is 0.06s of test execution. The sample is
recorded because it reproduces the regime the finding's "62s" came from and
shows the AFTER arm under 55s there.

**Negative runs — all three structural guards fail on the regression they target**
(temporarily reverted in the worktree, then restored):

   `TestDocumentationGateSharesTestCacheEntry` FAIL.
2. Drop `check-docs` from `check-essential` (gate leaves the commit path) →
   `TestCommitPathRunsDocumentationContract` FAIL.
3. Add a `testing.Short()` skip inside internal/release (a future short-gated

## Evidence

2026-09-17, worktree `/home/yale/quay-verify-upgrade-609dd467-root-worktrees/DIR-089`
(branch `task/DIR-089`). Delta: `Makefile` (one flag + contract comments),
`internal/release/commit_path_test.go` (new, +240 lines, test-only — the
DIR-078 package itself is untouched).

- **AC-1** — cold `make commit` executes internal/release exactly once
  (check-docs runs it; `test` then reports `(cached)`), vs twice before. Command
  trace and six timed runs in Measurement above. The mechanism: Go's test-result
  cache is keyed on the test binary's flag set, so check-docs' unflagged run
  created a cache entry the `-short` suite run could never reuse. Aligning
  check-docs on `-short` puts both in one entry. Landed the flag alignment
  rather than the Scope's other offered option (folding check-docs into `test`)
  because it is one line instead of a restructured prerequisite graph, and it
  keeps check-docs separately runnable and separately banner-labelled —
  `make check-docs` still reports the DIR-078 gate on its own.
- **AC-2** — three structural guards in `internal/release/commit_path_test.go`,
  each demonstrated failing on its target regression, plus one live end-to-end
  negative (`make commit` exit 2 on a fenced removed-tool example). See
  Measurement.
- **AC-3 / AC-4** — cold (`go clean -testcache`) 8.52–13.57s, warm 3.68–3.88s,
  build-cache-cold 49.62s; all ≤55s. Evidence above and in this section.
- **DoD-1** — `make commit` → exit 0 (`✅ Ready to commit`) on the final tree.
- **DoD-2** — not run here: landing is the fan-in driver's merge, so it carries
  `（待外部）`.
- **DoD-3** — cold/warm timings for both occurrences of the internal/release run
  are in Measurement.
- **Gate not weakened** — internal/release honors no short-mode skip (asserted);
  the DIR-078 contract tests are unchanged and still the sole thing check-docs
  runs. `-short` changes no test's behaviour in this package, so nothing is
  skipped that previously ran.
