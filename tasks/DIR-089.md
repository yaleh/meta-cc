## Finding

Measured 2026-07-30: `make commit` = check-essential + check-no-scanner + test ≈ 62s measured (budget says <60s). `check-essential` includes `check-docs` (the DIR-078 documentation contract gate), which runs `go test ./internal/release/...` — and the commit target's full `test` run re-tests that same package. internal/release is thus exercised twice per commit. Context: 33/36 recent tasks use `make commit` as acceptance, so the duplication compounds across 79 gate runs in 2 days (≈82 min total).

## Dependencies

Preserves the DIR-078 documentation contract gate; it must not be weakened on the commit path.

## Scope

Measure the actual cost of the double run (cache hit vs cold). Either reorder so the second run provably reuses Go's test cache, or fold check-docs into the test invocation with a documentation-constraint run marker — WITHOUT weakening the DIR-078 gate on the commit path. Attach measurement evidence to the task.

## Evidence

All timings from this task's worktree (`task/DIR-089`, post-develop-merge),
2026-09-14. `go clean -testcache` was run before every cold line below.

### The duplicate, isolated

| invocation | real | test time | cache |
| --- | --- | --- | --- |
| `go test ./internal/release/...` (check-docs' old flags), cold | 1.10s | 0.118s | executed |
| same flags again | 0.34s | — | `(cached)` |
| `go test -short ./internal/release/...` (the sweep's flags), after the above | 0.82s | 0.126s | **executed again** |
| `-short` again | 0.44s | — | `(cached)` |

**Root cause**: Go's test cache keys on the test binary's *arguments*, so a bare
run and a `-short` run of the same package are different cache keys. check-docs
ran bare; the `test` sweep runs `-short ./...`. The package therefore executed
twice per cold commit — the second execution was not a cache miss on a cold
cache, it was a miss on a *key that the first run never populated*.

### On the commit path

Each row is one `make commit`; the two `internal/release` lines are check-docs'
invocation first, the `test` sweep's second.

| build | run | check-docs | `test` sweep | wall |
| --- | --- | --- | --- | --- |
| before | cold | `0.047s` executed | `0.117s` executed | 10.2s |
| before | repeat, no clean | `(cached)` | `(cached)` | 4.5s |
| after | cold | `0.063s` executed | `(cached)` | 9.7s |
| after | cold | `0.047s` executed | `(cached)` | 9.2s |
| after | cold | `0.049s` executed | `(cached)` | 11.1s |
| after | cold (loaded machine) | `0.146s` executed | `(cached)` | 19.8s |

The sweep reporting `(cached)` is the proof of reuse: Go emits it only when it
reuses a prior result for that package under that exact flag set. One real
execution per cold commit.

Wall-clock is dominated by machine load (five worker sessions were in flight),
hence the 9.2–19.8s cold spread; the task-relevant signal is the `(cached)`
column, which is load-independent. Every run is far below the 55s AC. Warm
(`make commit` repeated, no `go clean`) measured 4.8–7.8s.

**The Finding's "≈62s" / "≈82 min" figures do not reproduce.** The dedupe is
still worth landing — it is free and removes a real double execution — but the
budget pressure the Finding cites was stale by the time the task ran: DIR-088
(status: done) has since demoted `check-path-independence` off the commit tier
(see `check-essential`, Makefile:58), which is what actually bought the tier its
headroom.

    doc_contract_test.go:379: removed-tool invocation: docs/guides/mcp.md:407 calls "query_user_messages", which is no longer registered.
          Accepted replacement: query_session_content(role="user").
          Fix the example, or—if this is an intentional labeled migration mapping—add docs/guides/mcp.md

`make commit` exits 2. The gate blocks the commit path and still names file,
line, stale claim, and accepted replacement. The violation was reverted and is
not part of the landed diff.

### Guard self-test

`-short` is now load-bearing for check-docs (it is what makes the cache keys
match), so the target fails **closed** if `internal/release` ever gains a
`testing.Short()` skip — which would otherwise let the gate pass while silently
skipping part of the contract. Adding a probe file containing `testing.Short()`
to `internal/release` and running `make check-docs`:

```
❌ DIR-089: internal/release now contains a testing.Short() skip.
make: *** [Makefile:282: check-docs] Error 1      (exit 2)
```

Removing the probe restores exit 0. `internal/release` contains no
`testing.Short()` today (verified by grep), so `-short` changes nothing about
*which* contract tests execute — it only aligns the cache key.

### Design choice

`check-docs` runs **first** in the commit chain (`check-essential` precedes
`test`, Makefile:352), so aligning *its* flag set — rather than reordering the
chain behind `test` — makes the **sweep** reuse **its** cache entry. The gate
therefore keeps genuinely executing on the commit path; the reorder alternative
would have demoted it to a cached no-op, which is the weaker of the two
strategies the Scope offers. No gate changed tiers, and the commit chain's
ordering is unchanged, so no workspace-cleanliness check moved after the suite.

### Deliberately out of scope

`check-release-ready` (Makefile:180) still runs
`go test ./internal/version/... ./internal/release/...` with bare flags. It is
not in the `commit` chain, so it exhibits the same latent flag asymmetry but is
not the double run this task scopes.
