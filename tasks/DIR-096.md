## Finding

During the 2026-07-30 dogfooding analysis session, `analyze_bugs` with `limit: 3` (examples per pattern) still produced 92KB (75 patterns) and was forced to file_ref mode. The `examples` entries are bare strings with no session/timestamp structure, and a consumer parsing them as objects hit AttributeError.

DIR-004's own finding noted analysis tools bypass the query pipeline entirely; DIR-019 (done) fixed total-error tracking but not output shape or pattern count. Today, even a modest per-pattern `limit` cannot prevent output blowup, because the pattern count itself is unbounded and defaults to everything (75 patterns on this project's 5-day corpus).

Compounding evidence from the same session: `query_sessions` hard-failed with `MCP error -32603: provider claude: no Claude entries in /home/yale/.claude/projects/-home-yale-work-meta-cc/8eda8f4e-2c74-4176-ba6b-8c45e890df42.jsonl` (tolerance tracked in DIR-094; time-window support for `analyze_bugs` tracked in DIR-095).

## Dependencies

Follows DIR-004 (done, pagination/file_ref) and DIR-019 (done, total-error tracking). Not a duplicate: this extends their contract to the bug-pattern analyzer's output shape and pattern count, which neither addressed.

## Scope

owner_repo: meta-cc

Give `analyze_bugs` a first-class pattern-count cap (`max_patterns`) and promote `examples` from bare strings to structured objects, so a default call fits the inline threshold and consumers can address each example without string parsing.

## Touches

- `internal/analysis/` (bug-pattern analyzer)
- `internal/mcp/tools/tools.go`
- tests under `internal/analysis/` and `internal/mcp/`

## Plan

1. Add a `max_patterns` parameter (default 20, 0 = unlimited), ranking patterns by recurrence/fix_count.
2. Reshape `examples` entries from bare strings to objects `{session_id, timestamp, error_text, fix_text?, signature}`.
3. Keep `stats_only` cheap (no example materialization when unset).
4. Update the tool schema in `internal/mcp/tools/tools.go` and wire the handler.
5. Add unit tests: cap enforcement, example object shape, and a corpus-level test asserting the default call stays under the inline threshold.

## Acceptance Criteria

- [ ] `max_patterns=5` returns at most 5 patterns.
- [ ] Every example carries `session_id` + `timestamp` + `error_text` (with `fix_text`/`signature` when available).
- [ ] A default (no-args) `analyze_bugs` call on this project's corpus fits the inline threshold (<32KB) instead of spilling to file_ref.
- [ ] `stats_only` does not materialize examples.
