## Finding

After the v3.6.0 user-scope upgrade, a new Codex session attempted to load `3.5.1/skills/prompt-find/SKILL.md` after that cache path had disappeared. The session then populated the 3.6.0 cache and recovered, proving an upgrade-time race between stale plugin discovery state and cache replacement. `make install-user` updates the shared source and purges only the Claude cache. `make install-user-codex` updates marketplace configuration but does not refresh or invalidate the Codex plugin cache. The current cache is healthy, but the same race can recur on the next upgrade.

## Contract

- A user-scope upgrade leaves Codex discovery metadata, cached plugin version, shared source manifest, skills, and MCP binary on one version before the install command reports success.
- Refresh uses a Codex-supported plugin-management mechanism when available and fails with an actionable message when consistency cannot be established.
- Cache replacement is atomic or otherwise preserves the previous usable version until the new version is complete; no startup window points at a deleted version directory.
- Running Codex sessions are not claimed to hot-reload. Output states clearly when a restart is required.
- Tests use an isolated `CODEX_HOME` and never mutate the developer cache.

## Plan

1. Reproduce stale discovery metadata plus an old cache in an isolated Codex home.
2. Determine the supported installed Codex CLI refresh/update flow and wrap it in the user-scope install path.
3. Add a safe compatibility fallback for CLIs without plugin refresh support, avoiding direct destructive cache deletion while stale metadata can still reference it.
4. Verify source manifest, resolved cache version, skill files, MCP command, and version identity after upgrade.
5. Document update/restart behavior and add a regression test covering consecutive version upgrades.

## Acceptance Criteria

- [ ] An isolated upgrade from version A to B starts the next Codex session without missing A-path skill warnings.
- [ ] No completed install has discovery metadata and cache/source manifests on different versions.
- [ ] The old usable cache is not removed before B is fully materialized and selected.
- [ ] Unsupported CLI refresh behavior fails visibly or preserves a safe previous installation.
- [ ] Installation documentation and automated tests cover upgrade and restart semantics.
- [ ] `make commit` passes.
