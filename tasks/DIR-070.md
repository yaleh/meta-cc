## Finding

After the v3.6.0 user-scope upgrade, a new Codex session attempted to load `3.5.1/skills/prompt-find/SKILL.md` after that cache path had disappeared. The session then populated the 3.6.0 cache and recovered, proving an upgrade-time race between stale plugin discovery state and cache replacement. `make install-user` updates the shared source and purges only the Claude cache. `make install-user-codex` updates marketplace configuration but does not refresh or invalidate the Codex plugin cache. The current cache is healthy, but the same race can recur on the next upgrade.

## Contract

- A user-scope upgrade leaves Codex discovery metadata, cached plugin version, shared source manifest, skills, and MCP binary on one version before the install command reports success.
- Refresh uses a Codex-supported plugin-management mechanism (`codex plugin add`) when available.
- After `codex plugin add` completes, the script verifies B is complete (all expected skill files, manifest, MCP binary present and version-consistent) before reporting success.
- On post-install verification failure the script exits non-zero with an actionable error that names the missing or inconsistent artifact and provides explicit manual recovery instructions (e.g. re-run `codex plugin add <plugin>@<previous-version>`). No automatic rollback is performed.
- The script verifies the MCP binary's self-reported version matches source and cache metadata (not just executability).
- Running Codex sessions are not claimed to hot-reload. Output states clearly when a restart is required.
- Tests use an isolated `CODEX_HOME` and never mutate the developer cache.

## Plan

1. Reproduce stale discovery metadata plus an old cache in an isolated Codex home.
2. Wrap `codex plugin add` in the user-scope install path; add post-install verification of all artifacts including binary-reported version.
3. On verification failure, emit actionable error with manual recovery command; do not attempt automatic rollback.
4. Add a compatibility fallback for CLIs without plugin refresh support that fails visibly with recovery guidance.
5. Verify source manifest, resolved cache version, skill files, MCP command, and binary-reported version identity after upgrade.
6. Document update/restart behavior and add a regression test covering consecutive version upgrades.

## Acceptance Criteria

- [ ] An isolated upgrade from version A to B that succeeds verification starts the next Codex session without missing A-path skill warnings.
- [ ] No completed install has discovery metadata, cache, source manifests, and MCP binary-reported version in disagreement.
- [ ] On post-install verification failure the script exits non-zero with an actionable error naming the missing/inconsistent artifact and providing an explicit manual recovery command; no automatic rollback is performed.
- [ ] Unsupported CLI refresh behavior fails visibly with actionable recovery guidance (no silent success, no destructive fallback).
- [ ] The fake Codex test double accurately models the real CLI's destructive replacement semantics (old cache removed before post-install verification).
- [ ] Installation documentation and automated tests cover upgrade and restart semantics.
- [ ] `make commit` passes.
