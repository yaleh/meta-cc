## Finding

Measured 2026-07-30: the Makefile `push` target currently runs the full Go test suite THREE times: `test` (short mode, inside `test-all`), a bare `go test -v ./...` (inside `test-all`), and `test-coverage-check` (`go test -coverpkg=./... -coverprofile=... ./...`). The documented `make push` budget is "<120s" but measured reality is far above it. Context: 79 acceptance gate runs in 2 days (≈82 min total), and 33/36 recent tasks use `make commit` as acceptance — push-tier waste compounds across the fleet.

## Dependencies

None

## Proposal

**What/Why**: `push:` (`Makefile:335`) chains `test-all` and `test-coverage-check`, which together produce three suite-executing `go test` runs over the full package list (`./...`). An exhaustive trace of every prerequisite of `push` finds **4 full-list `go test` invocations** in total: those three suite-executing runs plus one compile-only build check (item 4 below — it executes no tests and is a different, cheap category this directive does not eliminate):

1. `$(GOTEST) -short -v ./...` — recipe of `test` (`Makefile:526-528`), pulled in as a prerequisite of `test-all` (`Makefile:547`). Strict `-short` subset of run 2.
2. `$(GOTEST) -v ./...` — `test-all`'s own bare full recipe (`Makefile:549`), executed after its E2E prerequisites `test-e2e-mcp`/`test-e2e-codex` (`Makefile:530`, `Makefile:534`).
3. `@$(GOTEST) -coverpkg=./... -coverprofile=coverage.out ./... > /dev/null 2>&1` — `test-coverage-check` (`Makefile:729-730`); only its profile is consumed, by `bash scripts/checks/check-coverage.sh 80` (`Makefile:731`).
4. `go test -run=nothing -vet=off ./...` — compile-only, unconditional, at `scripts/checks/check-go-quality.sh:148`, reached via `check-build-quality` (`Makefile:66`) → `check-go-quality` (`Makefile:85-86`). Executes no tests (`-run=nothing`) and counts failures as a warning, not an error (`check-go-quality.sh:151`). The same script's other `go test` (`check-go-quality.sh:162`, the DIR-045 wiring gate) is scoped to `./internal/mcp/tools/...` — not a full-list invocation.

All remaining `push` prerequisites invoke no full-list `go test`: `check-code-quality` (`Makefile:62`), `check-comprehensive` (`Makefile:70`, whose `check-test-quality.sh` is pure grep), `test-bats` (`Makefile:139`), `lint` (`Makefile:658`), `build` (`Makefile:360`); `check-docs`' scoped run (`Makefile:258`) is not in `push`'s chain at all. Verified exhaustive count: **4** full-list invocations = **3** suite-executing runs (items 1–3 — the redundancy this directive eliminates, matching the Finding's triple) + **1** compile-only build check (item 4 — retained, see Out of scope). Runs 2 and 3 execute the identical non-short suite — run 3 merely adds coverage instrumentation and discards stdout — and run 3 never benefits from Go's test cache (coverage flags are outside the cacheable flag set), so every `make push` pays for ≥2 full suite executions even warm. The tier's stated budget is "<120s" (`Makefile:334`, help text `Makefile:759`).

**Approach**:

1. Merge runs 2+3: change `test-all`'s recipe (`Makefile:549`) from `$(GOTEST) -v ./...` to `$(GOTEST) -v -coverpkg=./... -coverprofile=coverage.out ./...` — one non-short pass that both gates the suite and produces the coverage profile (same shape as the existing `test-coverage-full` recipe, `Makefile:560`, minus its HTML step).
2. Delete run 3: shrink `test-coverage-check` (`Makefile:729-731`) to its threshold step only (`@bash scripts/checks/check-coverage.sh 80`), consuming the profile `test-all` produced. The script already fails closed on a missing `coverage.out` (`scripts/checks/check-coverage.sh:14-19`), so a missing profile cannot silently pass.
3. Delete run 1 from the push path: remove `test` from `test-all`'s prerequisites (`Makefile:547`) → `test-all: test-e2e-mcp test-e2e-codex`. The `test` target itself stays untouched — it remains the fast tier for `commit` (`Makefile:321`) and `check-commit-ready` (`Makefile:228`), which are not part of the triple. Coverage semantics are preserved: the merged non-short run covers everything `-short` ran plus the slow tests it skipped.
4. Preserve ordering (no semantic reordering): in `push`'s prerequisite list (`Makefile:335`) leave `test-all` ordered left of `test-coverage-check`; non-parallel make runs prerequisites sequentially left-to-right, so the profile exists before the threshold check reads it. E2E targets remain prerequisites of `test-all`, executing before its recipe exactly as today — the current bare full run (`Makefile:549`) already sits after E2E, and the merged run takes that identical slot. Coverage content is ordering-independent: `test-e2e-*` drive a prebuilt binary via bash (`Makefile:532`, `Makefile:543-545`) and contribute nothing to the Go profile.
5. Add a short DIR-086 contract comment above `test-all`/`test-coverage-check`: the push path contains exactly one suite-executing full-package-list `go test` (the compile-only `-run=nothing` check in check-go-quality.sh is a separate, retained category); tests and the 80% gate share its single profile; future additions must merge into this run, not add another.
6. Update only the two `help:` descriptions whose meaning changes — `test-all` (`Makefile:765`, now runs once with coverage) and `test-coverage-check` (`Makefile:768`, now reads the profile `test-all` produced); every other help line unchanged.

**Out of scope**:

- `test-coverage` (`Makefile:553-556`) and `test-coverage-full` (`Makefile:558-561`) ad-hoc targets — not in the push path (deleting `test-coverage-full`, now near-redundant, is a separate decision).
- The `commit` tier (`Makefile:321`) and `check-commit-ready` (`Makefile:228`) — their short-mode `test` runs stay; commit-tier speed unchanged.
- Scoped (non-full-list) runs: `check-docs`' `$(GOTEST) ./internal/release/...` (`Makefile:258`) and `check-release-ready`'s scoped run (`Makefile:184`) — not part of the triple.
- The compile-only build check `go test -run=nothing -vet=off ./...` (`scripts/checks/check-go-quality.sh:148`) — it executes no tests, counts failures as warnings only, and is cheap relative to the suite runs; eliminating it is a separate decision that would require touching the script, outside declared Touches.
- E2E script internals, bats, lint, build; the 80% threshold and `check-coverage.sh` logic (its "Run 'make test-coverage' first" hint drifts slightly — acceptable, the script stays untouched).
- `make -j` / parallel scheduling. Alias consumers `make all` / `make ci` / `check-push-ready` (`Makefile:354-358`, `Makefile:232`) inherit the change automatically and need no edit.

**Risks**:

- Losing the pre-push short run's fast-fail value: a red unit test now surfaces after ~30s of E2E instead of before it. Mitigation: the merged run occupies the exact slot of today's full run, failure output is identical, and the `commit` tier keeps short fast-fail for iteration; if needed later, E2E and the coverage run can swap order (coverage-neutral, per step 4).
- Cache-interaction surprises: runs 1 and 2 may hit Go's test cache on a warm machine (`-short`/`-v` are cacheable flags) while the `-coverprofile` run never caches — so warm-cache wall-time savings measure less than 3×, and cold runs (CI, after `go clean -testcache`) see the full elimination. Report measured before/after for both; the AC commits to ≤150s, not a fixed ratio.
- Stale-profile coupling: `test-coverage-check` alone now hits the script's missing-file branch instead of generating its own profile — fail-closed and visible, not silent — but a future edit adding `-j` or reordering `push`'s prerequisites could let the threshold read a stale `coverage.out` (the script cannot detect staleness). Mitigated by the DIR-086 comment contract (step 5).
- The merged run is coverage-instrumented, so it is marginally slower than today's bare run 2 alone — but strictly cheaper than runs 2+3 combined; net wall time drops.

## Scope

Restructure `test-all` / `test-coverage-check` so the full (non-short) suite runs exactly ONCE with `-coverpkg`/`-coverprofile` (tests + coverage in a single pass), with E2E targets running around it. Delete the redundant invocations. Keep the 80% coverage threshold check operating on that single profile. This is scheduling optimization, not coverage relaxation — every existing gate must survive.
