## Finding

In `internal/provider/claude/provider.go:117-142`, `findSessionFile` first tries `locator.FromSessionID(sessionID)`, and if that fails, falls back to listing all sessions and searching linearly. But when BOTH the original lookup AND the fallback listing fail, the function returns the original `err` from `FromSessionID` (not `listErr`). This silently discards the actual failure cause (e.g., "directory not found" or "permission denied"). Evidence: `return "", err` on lines 132 and 142 where `err` is from the original `FromSessionID` call, not the fallback listing error.

## Proposal

When the fallback listing fails with a non-nil `listErr`, return that error (the actual failure cause). When the fallback succeeds but finds no match, return the original `err` (session not found is the correct diagnosis). Also fix the same pattern on line 141 where linear search exhausts without a match.

## Plan

1. Fix `internal/provider/claude/provider.go:132-133` — change `return "", err` to `return "", listErr` when `listErr != nil`
2. Fix `internal/provider/claude/provider.go:141` — this one correctly returns `err` (session not found after linear search), but add a comment documenting why
3. Add test case: mock both `FromSessionID` and `AllSessionsFromProject` to fail, verify the returned error is from the listing failure
