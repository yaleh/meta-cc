## Finding

Measured 2026-07-30: `make check-essential` = 15.6s and includes `check-path-independence`, which spawns a nested `env -i PATH=/usr/bin:/bin make _path-independence-probe` (~5–8s of the 15.6s). `make commit` = check-essential + check-no-scanner + test ≈ 62s measured (budget says <60s). check-path-independence guards against regression of the Makefile's own PATH-hardening line (DIR-035) — the Makefile changes rarely, yet every `make commit` pays the nested-probe cost.

## Dependencies

None. Preserves the DIR-035 regression check; only its tier changes.

## Proposal

**What/Why**: `check-essential` lists `check-path-independence` among its prerequisites (Makefile:58), and the Tier-2 commit chain `commit: check-essential check-no-scanner test` (Makefile:321) — plus `check-commit-ready: check-essential test` (Makefile:228) — therefore runs it on every `make commit`. The check itself (Makefile:268–283) spawns a nested, PATH-stripped make subprocess, `env -i HOME=… PATH=/usr/bin:/bin $(MAKE) --no-print-directory -C $(CURDIR) _path-independence-probe` (Makefile:271), which resolves `go version` (Makefile:288–290) — a make-plus-go subprocess pair measured at ≈5–8s of the 15.6s `check-essential` total (Finding), pushing `make commit` to ≈62s against its <60s budget (comment at Makefile:320). It guards the Makefile's own `export PATH :=` hardening line (Makefile:10, DIR-035), which changes rarely — so every commit pays a push-tier concern's cost. Notably, `push:` itself (Makefile:335) does NOT depend on `check-essential` and does not run the probe today; only the push aggregator `check-push-ready:` (Makefile:232) reaches it, transitively via `check-essential`. The demotion must therefore ADD an explicit push-tier edge, not merely remove the commit-tier one.

**Approach**:

1. Makefile:58 — remove `check-path-independence` from `check-essential`'s prerequisite list, leaving `check-temp-files check-fixtures check-deps check-session-locator-scope check-docs`. Effect: `make commit` (Makefile:321) and `check-commit-ready` (Makefile:228) no longer spawn the nested `env -i` probe.
2. Makefile:335 — add `check-path-independence` as a prerequisite of `push:` (at the head of the list). Effect: every `make push` runs the DIR-035 probe; at ≈5–8s it fits the push tier's <120s budget (comment at Makefile:334) alongside the existing `test-all`/`test-coverage-check`/`test-bats`/`lint`/`build` chain.
3. Makefile:232 — add `check-path-independence` to `check-push-ready:`'s prerequisites, so this "Full validation for push" aggregator keeps the coverage it today inherits transitively through `check-essential`.
4. Makefile:781 — fix the `make check-essential` help text, which still advertises "PATH independence" as part of the essential group; the standalone `make check-path-independence` help line (Makefile:783) stays accurate.
5. Verify the graph move without any behavior change: `make -n commit` trace must contain no `env -i`/`_path-independence-probe` while `make -n push` must; then run the Plan's negative test (remove the `export PATH :=` line at Makefile:10, confirm `make push` fails at the probe, restore) and re-time `make check-essential`/`make commit` (expected ≥5s drop).

The probe recipe (Makefile:268–290) and the hardening line (Makefile:10) are untouched, so the check's failure semantics are identical — only the tier at which it fires changes.

**Out of scope**:

- The Makefile content-hash cache alternative floated in Scope — the direct edge move is chosen; caching remains a fallback only if push-tier timing regresses.
- `check-workspace-full` (Makefile:224): it no longer runs the probe after the move; it is the full-validation aggregator, not the commit/push gate (see Risks).
- Any change to the probe's `env -i` recipe, to `_path-independence-probe`, or to the `export PATH :=` line — regression behavior must stay byte-identical.
- CI workflows and scripts; Touches stay limited to `Makefile`.

**Risks**:

- A PATH-hardening regression could reach main via a flow that skips `make push` — e.g., a loop-driver or agent path that gates merges on `make commit` alone (the task's own `extra.acceptance` is `make commit`), or a manual `git push` bypassing Tier 3. Mitigation: the 3-tier workflow mandates `make push` before remote push, and the negative test (Plan step 4) proves the probe still fails when the hardening line is removed.
- `check-workspace-full` (Makefile:224) and `check-commit-ready` (Makefile:228) silently lose the check; the help-text fix (Approach step 4) documents the new tier placement so the change is discoverable.
- Push-tier wall time grows by the probe's ≈5–8s; `push`'s <120s budget has headroom, but the re-measurement in Approach step 5 must confirm and record it.

## Scope

Move `check-path-independence` out of `check-essential` into the push tier (or cache its result keyed on Makefile content hash). The regression check itself stays intact and must still fail if the `export PATH :=` hardening line is removed. Commit-tier gates otherwise unchanged.
