# `jq_filter`/`stats_first`/`offset`/`page_size` are dead parameters on all 6 analysis-service MCP tools

## Finding

Discovered during the DIR-045 adversarial audit (fresh-context, independently reproduced): the six
`analysis.Service`-backed MCP tools (`analyze_bugs`, `analyze_errors`, `quality_scan`,
`get_work_patterns`, `get_timeline`, `get_tech_debt`) are all built via `BuildTool(...)` in
`internal/mcp/tools/tools.go` and therefore get `jq_filter`, `stats_first`, `offset`, `page_size`,
and `include_subagents` merged into their schema via `StandardToolParameters()` — with convincing,
specific descriptions (e.g. `jq_filter`: "jq expression applied as a post-filter over this tool's
own already-produced result set...").

These six tools are registered via `registerHandler` (`internal/mcp/executor/analysis_handlers.go:6-11`),
which dispatches through `ExecuteSpecialTool` — a code path that `internal/mcp/executor/executor.go`'s
`ExecuteTool` (lines ~110-112) short-circuits and returns from *before* ever reaching
`NewToolPipelineConfig`/`pipeline.BuildResponse` (lines ~145-146), the only place `jq_filter`,
`stats_first`, `offset`, and `page_size` are ever consulted anywhere in this codebase.

Confirmed via a throwaway `GetToolDefinitions()` dump: `analyze_bugs`'s live schema genuinely
advertises `jq_filter` with the full post-filter description. Confirmed via
`grep -rn '"jq_filter"\|"stats_first"\|"offset"\|"page_size"\|"include_subagents"' internal/analysis/*.go`
— **zero hits**. These parameters are completely inert for all six analysis tools: passing
`jq_filter`, `stats_first`, `offset`, or `page_size` to `analyze_bugs`/`analyze_errors`/
`quality_scan`/`get_work_patterns`/`get_timeline`/`get_tech_debt` is silently ignored exactly like
the four already-fixed/filed instances of this defect class (`tasks/DIR-041.md` jq_filter,
`tasks/DIR-042.md` stats_only, `tasks/DIR-043.md` status, `tasks/DIR-044.md` output_format).

This is a **fifth** instance of the identical defect class on this MCP surface, and it is currently
masked by `tasks/DIR-045.md`'s own new static gate (`schema_param_wiring_test.go`), because that
gate's `allowedGenericParams` allowlist unconditionally exempts `jq_filter`/`stats_first`/`offset`/
`page_size`/`include_subagents` on the (here, false) assumption that they're consumed generically
regardless of tool. DIR-045 was routed to `needs-human` specifically because of this masking — this
task is the underlying live defect that needs its own fix, independent of whatever DIR-045's
allowlist ends up doing.

## Proposal

1. For each of the six `analysis.Service` tools, either:
   (a) wire `jq_filter`/`stats_first`/`offset`/`page_size` into `analysis.Service`'s methods the
   same way `stats_only` was wired in DIR-042 (a jq-post-filter stage, a stats-then-details mode,
   and pagination over the marshaled result), or
   (b) if these four parameters are not meant to apply to typed analyzer results (a legitimate
   design choice, since analyzer results are not flat record arrays the way consolidated-query-tool
   results are), remove them from these six tools' schemas (i.e., don't merge the full
   `StandardToolParameters()` set onto `registerHandler`-class tools — only merge the subset that
   genuinely applies) and update `docs/guides/mcp-query-tools.md` accordingly.
2. Whichever direction is chosen, ensure DIR-045's gate (or its eventual fixed version) reflects the
   real, per-tool truth rather than a blanket allowlist exemption.

## Acceptance Criteria

- [ ] `analyze_bugs({jq_filter: "select(false)"})` (and the same check for `stats_first`, `offset`,
      `page_size`) either measurably changes the response (if wired) or the parameter no longer
      appears in `analyze_bugs`'s MCP tool schema (if removed) — not silently ignored.
- [ ] The same before/after check passes for the other five analysis tools
      (`analyze_errors`, `quality_scan`, `get_work_patterns`, `get_timeline`, `get_tech_debt`).
- [ ] A committed Go test proves the chosen behavior for at least two of the six tools.
- [ ] `go test ./internal/analysis/... ./internal/mcp/...` passes.
- [ ] `make commit` passes.

## Definition of Done

      those tools' schemas) is landed on `main`, not left in a worktree.
- [ ] `docs/guides/mcp-query-tools.md` accurately reflects the now-consistent, real behavior.
- [ ] `make commit` passes.
