## Finding

The current MCP surface can search normalized content but lacks a metadata-first Codex session query and an exact `session_id` selector. `scope=session` means "most recent session" rather than an explicit Codex thread. Project queries load every matching rollout before jq filtering. Archived state, source kind, model provider, subagent lineage, thread status, title, and updated time are not first-class filters.

This makes targeted queries expensive and creates ambiguity between project scope, latest-session scope, and exact-thread scope.

## Dependency

Depends on DIR-029 so session discovery uses one backend-neutral contract across app-server and offline files.

## Proposal

Add a consolidated metadata-first MCP query for sessions and extend content/signal queries with precise Codex selectors. Preserve all existing defaults, especially Claude-only behavior when `provider` is omitted.

## Contract

- Add `query_sessions` or an equivalently consolidated mode that returns thread metadata without loading turns.
- Add exact `session_id` filtering to content, signal, timeline, and analysis paths where applicable.
- Support filters for cwd, archived, source kind, model/model-provider, status, parent/ancestor thread, created/updated time, title search, and include-internal/subagent behavior.
- Cursor pagination is stable and ordering is deterministic.
- `scope=session` remains backward compatible but documentation distinguishes it from exact `session_id`.
- Invalid or unsupported filters fail closed with actionable errors.
- A failure to load one session becomes a per-session warning when other sessions can still satisfy a project query.

## Plan

1. Define the session metadata response and shared filter structure.
2. Add schemas and strict argument validation for the new selectors.
3. Push supported filters into app-server/SQLite listing before deep turn loading.
4. Add exact-session fast paths that call `GetSession`/`thread/read` directly.
5. Make multi-session loading tolerate isolated corrupt/missing sessions with structured warnings.
6. Update MCP reference docs, examples, and cross-provider compatibility tests.

## Acceptance Criteria

- [ ] Listing session metadata does not parse rollout contents.
- [ ] Exact session lookup reads only the requested thread.
- [ ] Project and session scope cannot cross cwd boundaries.
- [ ] Archived, exec, alternate-provider, and subagent filters have fixture coverage.
- [ ] One corrupt rollout does not erase valid results from other sessions.
- [ ] Existing Claude-default schemas and results remain compatible.

## Definition of Done

- [ ] Tool schemas, handlers, docs, and tests describe the same filters.
- [ ] Query planning demonstrates metadata filtering before deep loading.
- [ ] `make commit` passes.
