## Finding

`contains` is documented at `tools.go:271-274` as applying to message content without restricting by role. But `consolidated_handlers.go:38-47` (role=user case) only reads `pattern` and `content_type`, never `contains`. Only the role=assistant case (lines 49-65) applies `contains`. Passing `contains: "error"` with `role=user` silently returns unfiltered results.

## Proposal

Either implement `contains` filtering for `role=user` using the same `regexp.QuoteMeta` + `test()` pattern, or document the restriction and return a clear error when `contains` is used with `role=user`.

## AC

- [ ] `contains` works for `role=user` OR a clear error is returned stating it's only for `role=assistant`
- [ ] Documentation updated to reflect actual behavior
