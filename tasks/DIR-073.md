## Finding

Provider-aware tools hard-code an omitted or empty `provider` to `claude` in handler, pipeline, query-session, stage-1, and raw-file paths. Both plugin MCP manifests start the same binary with an empty environment, so the server cannot distinguish Claude Code from Codex. A live call from a Codex session to `query_sessions` without `provider` returned only Claude sessions. This violates the required default: when meta-cc is invoked from Claude Code it should search Claude Code history, and when invoked from Codex it should search Codex history.

## Contract

- Every provider-aware tool resolves an omitted `provider` to the host that launched the MCP server: Claude Code maps to `claude`, Codex maps to `codex`.
- Explicit `provider=claude`, `provider=codex`, or `provider=all` always overrides the host default unchanged.
- Claude and Codex plugin manifests inject a validated host/default-provider value into the same MCP binary; routing logic has one source of truth rather than scattered string defaults.
- Manual or standalone MCP installations have a documented deterministic fallback and can set the default explicitly without changing query arguments.
- Responses preserve provider provenance so callers can verify which corpus was searched.
- Invalid host/default-provider configuration fails visibly rather than silently reading the wrong history.

## Plan

1. Add a central default-provider resolver with a narrowly scoped environment/config contract.
2. Set the Claude plugin MCP manifest to `claude` and the Codex plugin MCP manifest to `codex`.
3. Replace every hard-coded omitted-provider default in schemas, handlers, pipelines, stage tools, raw-file selection, analysis dispatch, and `query_sessions`.
4. Keep explicit provider parsing and backward compatibility for standalone users through a documented fallback.
5. Add table-driven and process-level tests using identical synthetic Claude and Codex corpora under both host environments.
6. Update tool descriptions and installation/integration documentation to say default means current host, not always Claude.

## Acceptance Criteria

- [ ] In a Codex-launched MCP process, `query_sessions` and `query_session_content` without `provider` return only Codex history.
- [ ] In a Claude-launched MCP process, the same calls return only Claude history.
- [ ] `get_session_directory`, `get_session_metadata`, signals, timeline, and every other provider-aware tool use the same host default.
- [ ] Explicit provider values override the host default for all tools.
- [ ] Both packaged manifests and user-scope installation tests preserve the correct host marker.
- [ ] Invalid configuration is actionable and standalone fallback behavior is documented and tested.
- [ ] `make commit` passes.
