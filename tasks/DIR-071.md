## Finding

DIR-065 correctly fixed accumulation of multiple `last_token_usage` events within a turn, but two broader semantic losses remain. The SQLite `threads.tokens_used` aggregate is stored in `TokenUsage.InputTokens` even though it is not an input-token count, and rollout `reasoning_output_tokens` is parsed only as a condition for nonzero usage but is not retained in the canonical model. Callers can therefore mistake an opaque session aggregate for input usage and cannot reconcile reasoning-inclusive totals.

## Contract

- Canonical usage distinguishes input, cached input, output, reasoning output, and opaque or aggregate totals when the source provides them.
- SQLite `tokens_used` is preserved with explicit provenance and is never mislabeled as input tokens.
- Rollout per-call, per-turn, and cumulative totals retain their source and aggregation semantics.
- Normalized MCP output remains backward compatible where values were already correct, while ambiguous legacy fields are documented and migrated without silent numerical reinterpretation.
- Session totals and per-turn sums expose explainable differences such as compaction, missing events, and reasoning tokens.

## Plan

1. Extend the canonical token model with reasoning and aggregate/provenance fields.
2. Map app-server, rollout, and SQLite sources separately rather than forcing them into one shape.
3. Update record normalization, token signal queries, stats, schemas, and documentation.
4. Add fixtures with cached input, reasoning output, multiple calls, missing token events, and SQLite-only metadata.
5. Add compatibility tests that prevent `tokens_used` from reappearing as `input_tokens`.

## Acceptance Criteria

- [ ] `reasoning_output_tokens` survives parsing and appears in token query output.
- [ ] SQLite-only `tokens_used` is labeled as an aggregate with source metadata, not as input tokens.
- [ ] Multi-call turn totals still satisfy DIR-065 accumulation behavior.
- [ ] Tests explain and verify reconciliation between turn and session totals.
- [ ] Tool schemas and user documentation define every token field and provenance.
- [ ] `make commit` passes.
