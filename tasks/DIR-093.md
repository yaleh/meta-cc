## Plan

1. Read DIR-010's landed gate text to understand the existing
   read-before-edit rule; extend it rather than forking a new gate.
2. Add coverage for nonexistent-file Reads (6 recurrences): dispatch prompts
   should embed verified file paths; when unsure, agents must glob/grep to
   confirm a path before Read.
3. Add coverage for empty optional parameters (4 recurrences): never pass
   empty-string values to optional parameters such as Read's `pages`; omit
   the parameter entirely instead.
4. Keep the existing read-before-edit rule (3 recurrences) intact.
5. For each of the three classes, include one concrete bad/good example.
6. Add a measurable review step: re-check recurrence via
   meta-cc analyze_errors over the trailing 7 days.
7. Update docs/guides/plugin-development.md to reference the extended gate.

## Implementation

Extended `docs/guides/plugin-development.md` with a new "Subagent Dispatch
Prompt Gate" section (the gate block is written to be pasted verbatim into a
dispatch prompt, so it is gate text and not only prose about gate text):

- Clause 1 — READ BEFORE EDIT, DIR-010's rule kept with its original wording
  ("ALWAYS Read a file before Editing it. The code in this prompt may be
  stale."), extended in place rather than forked into a second gate.
- Clause 2 — new: verify a path before reading it (nonexistent-Read class).
- Clause 3 — new: never pass an empty value to an optional parameter
  (empty-`pages` class).

Each clause carries one concrete bad/good example, quoted with the error text
that class actually produces where the corpus contains it. The section records
the baseline counts with their analyzer signatures (6 / 3 / 4 for
c10431437d701636 / fa9c208b72b8ee6c / 85c85a050441de2f) and documents the
trailing-7-day follow-up procedure expecting zero recurrences.
