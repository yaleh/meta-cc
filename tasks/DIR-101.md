## Finding

Every landing commit that carries quay-native-written board files fails pre-commit once and rewrites the batch: board files (`tasks/*.md`, `docs/architecture/adr/*.md`) are written without a trailing newline, so the `end-of-file-fixer` hook exits 1 with `files were modified by this hook`, mutates N files on disk, and forces a commit retry. This churn recurs on every routine/loop landing cycle — there is no mechanical enforcement that board files are EOF-clean before commit.

Evidence:

- Session `02d6f16b-7ae7-4bae-9963-6c0d07dfcbb1` (2026-07-30T17:29:20Z): `fix end of files.........................................................Failed / - hook id: end-of-file-fixer / - exit code: 1 / - files were modified by this hook / Fixing tasks/DIR-096.md / Fixing tasks/DIR-091.md / Fixing tasks/DIR-086.md / Fixing tasks/DIR-095.md / ...` — 16 task files (`DIR-082` .. `DIR-099`, the entire recent routine-filed batch) rewritten in one landing.
- Session `77187c1c-e203-42d0-985a-8684b11fe333` (2026-07-30T13:09:51Z): `fix end of files...Failed ... Fixing tasks/DIR-081.md / Fixing docs/architecture/adr/ADR-009-query-execution-result-consumption-cont...` — then the same hook re-run at `13:11:11Z` and `13:16:17Z` shows `fix end of files.........................................................Passed` — the classic fail → mutate → retry loop, and it reaches ADR files too, not just tasks.
- Session `2895bdb9-1e32-4af8-9906-73db13b7a584` (2026-07-30T02:55:09Z): `fix end of files...Failed ... Fixing .claude/workflows/execute-milestone.js` — the writer's EOF omission is not a one-off.

Recurrence pattern: the routine track files/lands board files in every cycle (history-mining, drain, milestone landing), so this hook failure is per-cycle, deterministic, and self-healing only by mutation+retry — costing a failed commit plus a dirty re-stage each time.

Boundary note: the root writer (quay-native provider's file serializer) lives in a different repo; an upstream fix is report-only per the quay workspace boundary rule. DIR-092 covers the adjacent goimports/pre_commit hook issues but not EOF on board files. This task installs the boundary fix that belongs to this repo: mechanically normalize trailing newlines on board files at the land/commit boundary so the hook passes first-try.

## Proposal

**What/Why**: Every landing commit that carries quay-native-written board files fails pre-commit once and rewrites the batch, because board files are serialized without a trailing newline and `.pre-commit-config.yaml:120-122` registers the upstream `end-of-file-fixer` hook ("Ensure files end with newline", in the pre-commit-hooks v4.5.0 block at `.pre-commit-config.yaml:108-110`), which exits 1 with `files were modified by this hook`, mutates every dirty file on disk, and aborts the commit (`fail_fast: false` at `.pre-commit-config.yaml:143` does not rescue this — any failing hook still stops the commit). The Finding's session evidence shows this is per-cycle: `02d6f16b-7ae7-4bae-9963-6c0d07dfcbb1` (2026-07-30T17:29:20Z) rewrote 16 task files (`DIR-082`..`DIR-099`) in one landing; `77187c1c-e203-42d0-985a-8684b11fe333` shows the fail → mutate → retry loop reaching `docs/architecture/adr/ADR-009-...` before `Passed` at 13:11/13:16; `2895bdb9-1e32-4af8-9906-73db13b7a584` hit `.claude/workflows/execute-milestone.js`. Cheap verification today (2026-07-30, `tail -c 1 | xxd -p`): 110 of 111 files under `tasks/*.md` + `docs/architecture/adr/*.md` already end in `0x0a` — the hook's own prior mutations, landed by retry — while `tasks/MCTEST.md` is still EOF-dirty (last byte ≠ `0x0a`), a live specimen of the class: any fresh board file lands dirty and is rewritten at the next commit. The root writer (quay-native's file serializer) lives in a different repo and is report-only per the quay workspace boundary rule; this task installs this repo's boundary fix — mechanically normalize board-file EOF at the land/commit boundary so `end-of-file-fixer` passes first-try.

**Approach**:

1. Add `scripts/gates/normalize-board-eof.sh`, modeled on the existing Tier-1 hygiene-gate pattern in `scripts/gates/tree-hygiene-check.sh` (DIR-031): an idempotent fixer that scans exactly `tasks/**/*.md` and `docs/architecture/adr/**/*.md` and appends a single `\n` to any file whose last byte is not `0x0a`. A `--check` flag instead lists dirty files and exits 1 without mutating (for gating/CI); default fix mode exits 0 and prints the files it touched. Append-only at EOF — never rewrites line endings or file bodies.
2. Add a `normalize-board-eof:` make target invoking the script, and wire it as the first dependency of `commit:` (`Makefile:321`, currently `commit: check-essential check-no-scanner test`). Because this board's acceptance gate is `extra.acceptance: make commit`, every pre-land gate run normalizes EOF on disk *before* the land commit stages files — the mutation happens outside the pre-commit transaction, so no hook ever reports `files were modified by this hook`.
3. Register `normalize-board-eof` in `.PHONY` (`Makefile:47`) and add a `make help` line (`Makefile:753+`, Quality Gates section) describing it as the board-file EOF normalizer backing the land boundary.
4. Document the boundary in `docs/guides/git-hooks.md` (the existing hooks/integration doc): what the normalizer fixes, the two board globs, the `make commit` wiring, manual invocation, and that `end-of-file-fixer` remains as defense-in-depth for non-board files.
5. Deliberately leave `.pre-commit-config.yaml` untouched — this is not a hook-ordering fix: pre-commit aborts any commit in which a hook mutates the worktree, so a normalizer placed earlier in the hook chain would reproduce the identical mutate → retry cycle under a different hook name. Only a boundary that runs before the commit transaction starts (the make target) can produce a first-try pass.

**Out of scope**:

- The upstream quay-native file-serializer fix — a different repo, report-only per the quay workspace boundary rule (per the Finding's boundary note).
- Any change to `.pre-commit-config.yaml` (no reordering, no new hook, no `end-of-file-fixer` exclusion): the hook stays as a catch-all safety net for non-board files, and a hook-resident normalizer cannot achieve a first-try pass (Approach step 5).
- DIR-092's adjacent goimports/pre-commit issues.
- Non-board files (Go sources, `.claude/workflows/*.js`): the globs stay scoped to `tasks/**` and `docs/architecture/adr/**` per AC-1.
- A `.githooks/`-based pre-commit shim: `.githooks/` is absent from this checkout (`scripts/install/install-hooks.sh:6-16` expects it and would error), so the make-target boundary is the load-bearing integration point.

**Risks**:

- Worktree mutation during `make commit`: files fixed by the normalizer must be staged by the land path after the gate runs. The loop's land flow (`git add` of board/audit files in `.claude/workflows/execute-milestone.js`) already re-stages post-gate, and `--check` mode turns any future drift into a loud gate failure instead of a silent one.
- Fixer scope creep: mitigated mechanically — the script hard-codes the two board globs and is append-only at EOF (no line-ending rewrites, no CRLF stripping), so it cannot churn file bodies or touch out-of-scope paths; AC-3 requires the idempotence demonstration.
- Latency on `make commit`: scanning ~111 small markdown files is sub-100ms, negligible against the <60s commit-tier budget (CLAUDE.md tier definitions).
- The `trailing-whitespace` hook with `--markdown-linebreak-ext=md` (`.pre-commit-config.yaml:115-118`) is a distinct failure class and is not addressed here.
