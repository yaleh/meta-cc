## Finding

Subagents launched into git worktrees for milestone execution regularly fail with
`go: command not found` (6 occurrences across 5 subagents in 2 sessions) and
`No module named pre_commit` (2 occurrences across 2 sessions). Each failure costs
turn budget and error-recovery cycles. Evidence:

- Session `2a38491e`, subagent a2adaa1c33762b335 (DIR-003 build): 2x `go: command not found`
- Session `2a38491e`, subagent a4bfbb874675fb340 (DIR-001 build): `go: command not found`
- Session `2a38491e`, subagent accd3f1c38e10f5c0 (DIR-003 test fix): `go: command not found`
- Session `eb482896`, subagent a22601ecb907a37ac (DIR-007 build): `go: command not found`
- Session `eb482896`, subagent a3380b9b6153c6114 (DIR-006 audit): `go: command not found`

## Proposal

Add a `worktree-env` gate registered in `.quay/gates.yml` that validates the
worktree environment before subagent dispatch. The gate runs `go version` and
`python3 -c "import pre_commit"` and fails-closed if either is missing.
The loop-driver skill checks this gate before launching build subagents.

## AC

- [ ] `worktree-env` gate registered (appears in `quay gate --list`)
- [ ] Gate fails when `go` is not on PATH
- [ ] Gate fails when `python3 -c "import pre_commit"` fails
- [ ] Gate passes when both Go and pre_commit are available

## DoD

- [ ] Gate script executable and tested standalone
- [ ] Loop-driver skill updated to invoke gate pre-dispatch
