## Finding

`analyze_errors` groups errors `by_type` using opaque SHA hashes (e.g., `00fe62be6467099b: 6x`)
instead of human-readable labels. The by-tool breakdown (`by_tool`) is immediately useful,
but the by-type view is nearly useless without drilling into each example. An agent or human
reading the output cannot distinguish "permission_blocked" from "stale_read" from
"file_too_large" without following the example links.

## Proposal

Add a `by_type_label` or replace the SHA-keyed grouping with human-readable error type
labels derived from the error signature (e.g., "permission_blocked", "tool_not_available",
"stale_read", "json_parse_error").

## Acceptance Criteria

- [ ] `analyze_errors` by-type output uses human-readable labels instead of SHA hashes
- [ ] Each label maps to a distinguishable error pattern
- [ ] Backward-compatible: SHA hashes preserved as secondary key or in details
