## Finding

`query_session_content(role="user", provider="codex")` silently returns an empty result when
`context_turns > 0`, even though the identical query without context returns real matches.
This is a false-negative search result, not an unavailable-provider or no-history condition.

The defect was reproduced against `/home/yale/work/quay`:

```text
pattern="吞吐", context_turns omitted
  -> 8 matching user messages across 5 Codex sessions

pattern="吞吐", group_by_session=true
  -> 5 non-empty session groups

pattern="吞吐", context_turns=2
  -> 0 records, warnings=[]
```

The Claude provider behaves differently and correctly: a live
`provider="claude", pattern="DIR-120", context_turns=1` query returned the matched user record
plus adjacent records with `context:false/true`. The existing Claude-shaped context-window unit
tests also pass.

The current implementation is structurally provider-specific despite the MCP schema advertising
`context_turns` as a provider-neutral `role=user` option:

1. `internal/mcp/pipeline/pipeline.go` calls `mcp/query.GetQueryBaseDir(scope, workingDir)` without
   passing `provider`. That locator resolves the Claude project/session directory.
2. `internal/mcp/filters/filters.go:ExpandContextTurns` identifies matched records by Claude
   `uuid + sessionId`, then directly rescans JSONL files in that directory.
3. Codex queries are produced through `internal/provider/records.Normalize`. Those records carry
   `sessionId` but no Claude `uuid`; their backing rollout/app-server histories are not Claude
   normalized JSONL files in the Claude project directory.
4. No matched Codex record can therefore be mapped back to a loaded turn. The window set remains
   empty and the pipeline replaces valid matches with `[]` without an error or warning.

Existing context-turn tests use Claude-shaped fixtures with top-level `uuid` and `sessionId`.
There is no Codex end-to-end test covering `context_turns`, which allowed the provider-parity
regression to ship.

## Proposal

Make context expansion operate on provider-neutral, canonical session records rather than reaching
behind the provider abstraction to rescan Claude JSONL.

The preferred design is:

1. Preserve a stable logical identity and order for normalized records (for example provider,
   session ID, canonical turn ID/index, and record/item position as needed). Do not identify turns
   by timestamp alone because multiple records in one turn can legitimately share a timestamp.
2. When context is requested, load the relevant full session through the selected provider
   (`claude`, `codex`, or each provider represented by `all`) and normalize it through the same
   projection used by the original query.
3. Locate each matched record in that canonical ordered session stream, expand the bounded window,
   merge overlapping windows without duplicates, preserve chronological/session order, and mark
   matches `context:false` and surrounding records `context:true`.
4. Keep current Claude behavior and output compatibility unless an intentional contract correction
   is separately documented and tested.
5. If a selected provider/backend cannot supply the required context, return an explicit,
   actionable error or warning while retaining the original matches. Never silently turn a
   non-empty match set into an unqualified empty result.

A narrowly provider-specific Codex rollout scan is not sufficient: Codex supports both rollout and
app-server backends, and duplicating their parsing in `filters.go` would bypass deduplication,
completeness, compaction, and backend-selection behavior already owned by the provider layer.

## Contract

- For every supported provider, enabling `context_turns=N` never removes the matched records that
  the same query returns with `context_turns=0`.
- Up to `N` surrounding logical records on each side are returned from the same session only;
  windows are bounded at session edges and overlapping windows are deduplicated.
- Matched records have `context:false`; added records have `context:true`.
- Provider, session identity, chronological order, message content, and Codex duplicate-suppression
  semantics are preserved.
- `group_by_session`, pagination, `content_summary`, compact-summary exclusion, `scope=session`,
  explicit `session_id`, and `provider=all` either compose correctly with context expansion or fail
  with a documented validation error. They must not silently erase data.
- Claude behavior remains backward compatible.
- Rollout and app-server Codex backends obey the same public context-window contract.

## Plan

1. Add a RED Codex end-to-end fixture with at least five ordered turns. Match the middle user
   message and prove `context_turns=1` currently returns zero rather than the match plus context.
2. Add a Claude/Codex provider-parity test over equivalent logical histories.
3. Introduce the minimum stable canonical record identity/order needed for provider-neutral window
   expansion; preserve public fields and existing query filters.
4. Route context loading through the provider/session abstraction and remove the pipeline's
   dependency on a provider-blind Claude base directory for this feature.
5. Cover boundary windows, overlapping matches, multiple sessions, `group_by_session`,
   `scope=session`, explicit `session_id`, `provider=all`, compact summaries, and both Codex
   backends.
6. Document the context-counting/ordering semantics and backend failure behavior.
7. Run focused tests, the complete Go suite, lint/error checks, and the repository commit gate.

## Acceptance Criteria

- [ ] The exact Codex reproduction that returns 8 matches without context returns all 8 matched
  records plus appropriate adjacent context when `context_turns=2`.
- [ ] A Codex five-turn fixture matching the middle turn returns a bounded, ordered context window
  with correct `context` flags.
- [ ] Claude and Codex produce equivalent logical windows for equivalent fixtures without
  regressing the existing Claude output contract.
- [ ] Codex rollout and app-server fixtures both pass the context-window contract.
- [ ] `context_turns + group_by_session` returns non-empty correctly grouped Codex results.
- [ ] Boundary and overlapping windows are deduplicated and never cross session boundaries.
- [ ] Context expansion failure is explicit and retains or clearly reports the original matches;
  no non-empty match set becomes `data:[]` with `warnings:[]`.
- [ ] The tool schema/reference documentation accurately describes provider support and context
  ordering/counting semantics.
