## Finding

`internal/analysis/service.go:147-150` (`loadData`) silently `continue`s when `ParseEntries()` fails on a session file — no log, no warning, no record. If 80% of session files are corrupted, analysis returns results from the remaining 20% with zero evidence of data exclusion. Analysis result types (`BugAnalysisResult`, `TechDebtResult`, etc.) have no `Warnings` field, and MCP handlers only pass through the JSON result, so skipped files are never surfaced to callers.

## Proposal

Accumulate parse-failure warnings per file in `loadData`; add a `Warnings []string` field to the analysis result types; log each skipped file at WARN level (with file path and parse error); surface the warnings in MCP tool responses so callers can see data was excluded.

## Plan

1. In `loadData`, collect `{file, error}` for each skipped file and WARN-log it.
2. Add `Warnings []string` to the analysis result types produced from `loadData` output.
3. Populate `Warnings` from the collected skip records.
4. Add tests: a corpus with a malformed file yields results plus a warning naming that file.
