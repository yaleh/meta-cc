## Finding

`CLAUDE.md`'s FAQ states as an unconditional rule: **"Q: How much code can I write in one
phase? A: ... See [docs/core/principles.md]"** and the "Core Constraints" section states:

> **Test Coverage**: >=80%
> **Testing Protocol**: Run `make commit` after each Stage.

`docs/core/principles.md:278` states the same target explicitly: `测试覆盖率目标：>= 80%`
("Test coverage target: >=80%").

Two independent, verifiable gaps exist between this documented contract and the actual Makefile
implementation:

**1. The coverage gate is never wired into any of the workflow targets CLAUDE.md itself
documents.** `Makefile:702-704` defines:

```makefile
test-coverage-check:
	@$(GOTEST) -coverpkg=./... -coverprofile=coverage.out ./... > /dev/null 2>&1
	@bash scripts/checks/check-coverage.sh 75
```

But grepping the entire `Makefile` for `test-coverage-check` shows it is referenced in exactly two
places: its own rule definition (line 702) and the `help` target's echo text (line 741) — it is
**not** a dependency of `commit`, `push`, `pre-commit`, `ci`, `check-essential`,
`check-comprehensive`, `check-code-quality`, `check-build-quality`, or `test-all`:

```
$ grep -n "^commit:\|^push:\|^pre-commit:\|^ci:\|^test-all:\|^check-essential:\|^check-comprehensive:\|^check-code-quality:\|^check-build-quality:" Makefile
297:commit: check-essential test
311:push: check-code-quality check-build-quality check-comprehensive test-all test-bats lint build
326:pre-commit: commit
332:ci: push
520:test-all: test test-e2e-mcp test-e2e-codex
43:check-essential: check-temp-files check-fixtures check-deps check-session-locator-scope check-path-independence
47:check-code-quality: check-formatting check-mod-tidy
51:check-build-quality: check-plugin-sync check-go-quality check-imports
55:check-comprehensive: check-scripts check-debug check-test-quality
```

None of these expand (directly or transitively) to `test-coverage-check`. CLAUDE.md's own
documented workflow is exactly `make dev` -> `make commit` -> `make push`, and separately
"Testing Protocol: Run `make commit` after each Stage" — a contributor following CLAUDE.md's
instructions to the letter, including running `make push`/`make ci` before every push, will never
have test coverage checked at all. The only way to invoke the coverage gate is to run
`make test-coverage-check` by name, which is not mentioned anywhere in CLAUDE.md, in
`docs/core/principles.md`, or in any other guide under `docs/guides/` (checked via
`grep -rn "test-coverage-check" docs/` — no results).

**2. Even if invoked, the one existing gate checks 75%, not the documented 80%.** The gate's own
default and the value the Makefile passes are both `75`, not `80`:

```
$ cat scripts/checks/check-coverage.sh | head -8
#!/bin/bash
# Check test coverage meets threshold
# Usage: ./check-coverage.sh [THRESHOLD]
#   Default threshold: 75% (adjusted for -short mode which skips integration tests)
set -e
THRESHOLD=${1:-75.0}
```

and `Makefile:704` calls it as `bash scripts/checks/check-coverage.sh 75` — explicitly 75, never
80. `make help`'s own text at `Makefile:741` even advertises the wrong number to a contributor
who greps for it: `"make test-coverage-check     - Check test coverage meets 75% threshold"` —
directly contradicting CLAUDE.md's "Test Coverage: >=80%" a few files away in the same repo.

Current actual coverage is 81.4% (`go test -short -coverpkg=./... -coverprofile=... ./...` then
`go tool cover -func=coverage.out | grep total` -> `total: (statements) 81.4%`), so today's
codebase happens to clear both the documented 80% and the implemented 75% threshold — but nothing
in the standard `make commit`/`make push`/`make ci` pipeline would catch a regression below either
number, since the check that would is never invoked automatically.

## Proposal

1. Wire `test-coverage-check` (or a `-short`-mode-appropriate variant) into `push` (the "full check
   before push" target CLAUDE.md documents), so a coverage regression actually fails CI/`make push`
   rather than silently passing.
2. Reconcile the threshold: either raise `check-coverage.sh`'s default/the Makefile's passed value
   to 75 -> 80 to match CLAUDE.md/`docs/core/principles.md`, or lower the documented target in both
   `CLAUDE.md` and `docs/core/principles.md` to 75 with the same "-short mode" rationale already
   captured in the script's own comment — whichever reflects the intended real policy — so the
   three sources (`CLAUDE.md`, `docs/core/principles.md`, `check-coverage.sh`/`Makefile`) agree.
3. Update `make help`'s text (`Makefile:741`) to match whatever the reconciled number is.

## Acceptance Criteria

- [ ] `grep -n "test-coverage-check" Makefile` shows it appears as a dependency of `push` (or
      another target that `push`/`ci` transitively reaches), not only in its own rule and the
      `help` text.
- [ ] The threshold value passed to `check-coverage.sh` in the `Makefile`, the default inside
      `scripts/checks/check-coverage.sh`, `CLAUDE.md`'s "Test Coverage" line, and
      `docs/core/principles.md`'s "测试覆盖率目标" line all state the identical percentage.
- [ ] A deliberately-introduced coverage drop (e.g. temporarily commenting out a well-covered
      test file in a scratch branch) causes `make push` to fail at the coverage step — verified by
      an actual run, not narrative claim.
- [ ] `make commit` and `make push` both pass on the current `main` after the change (today's 81.4%
      coverage satisfies whatever reconciled threshold is chosen).

## Definition of Done

- [ ] The wiring and threshold-reconciliation changes are landed on `main`.
- [ ] `make push`'s output visibly includes a coverage-check step and its pass/fail status.
- [ ] All three textual sources of the coverage requirement (CLAUDE.md, docs/core/principles.md,
      check-coverage.sh/Makefile help text) state one consistent number.
- [ ] `make commit` passes.
