# Dead commit/build-time LDFLAGS injection, and no way to detect that a running installed MCP server predates HEAD

## Finding

While mining this session's history for the current DIR-045/DIR-048 "dead parameter" defect class, I
re-verified `analyze_bugs`'s *live* MCP tool schema (fetched via `ToolSearch` against the actually
running `mcp__plugin_meta-cc_meta-cc__analyze_bugs` tool in this very session) and found it still
advertises `jq_filter`, `stats_first`, `offset`, and `page_size` as accepted parameters — exactly the
four parameters that commit `78aea25` (`fix(mcp): scope jq_filter/stats_first/offset/page_size off
the 6 analysis-service tools`, landing DIR-048) is supposed to have stripped from
`AnalysisStandardToolParameters()` in `internal/mcp/tools/tools.go:81-101`.

This is **not** a regression of DIR-048 in source — `internal/mcp/tools/tools.go` on `main` (HEAD =
`78aea25`) correctly omits those four keys for `analyze_bugs`/`analyze_errors`/`quality_scan`/
`get_work_patterns`/`get_timeline`/`get_tech_debt`. The live discrepancy is because **the actually
running MCP server process is stale relative to HEAD**, and nothing detects or surfaces that fact:

```
$ git log -1 --format="%H %ci" 78aea25
78aea2568ba95b71a76758c606fe75a509c6ae01 2026-07-28 15:56:09 +0000

$ ps aux | grep meta-cc-mcp
yale  2508705 ... /home/yale/.local/share/meta-cc//bin/meta-cc-mcp   (started 15:13, i.e. before HEAD landed)
yale  1105556 ... /home/yale/.local/share/meta-cc//bin/meta-cc-mcp   (started Jul27)
...

$ stat /home/yale/.local/share/meta-cc/bin/meta-cc-mcp
Modify: 2026-07-28 08:55:51   # built ~7 hours BEFORE commit 78aea25 landed

$ /home/yale/.local/share/meta-cc/bin/meta-cc-mcp   (startup log)
{"msg":"MCP server starting","server_name":"meta-cc-mcp","version":"3.5.1"}
```

The user-scope installed binary that this very Claude Code session's MCP tool calls are served from
(`~/.local/share/meta-cc/bin/meta-cc-mcp`, installed via `make install-user`, per `Makefile:389-401`)
predates the DIR-048 fix commit, yet reports the identical version string (`3.5.1`) that a
freshly-rebuilt binary would also report — `release.json`'s version is a manually-bumped release
number (`internal/version/release.json`, bumped only in dedicated `chore: release vX.Y.Z` commits),
not a per-commit fingerprint, so **two materially different builds are indistinguishable from their
own self-reported version**.

Root cause of why no fingerprint exists: the Makefile *appears* to already inject exactly this
information via linker flags, but the injection is dead:

```makefile
# Makefile:12-17
VERSION ?= $(shell git describe --tags --always --dirty 2>/dev/null || echo "dev")
COMMIT ?= $(shell git rev-parse --short HEAD 2>/dev/null || echo "unknown")
BUILD_TIME ?= $(shell date -u '+%Y-%m-%d_%H:%M:%S')
LDFLAGS := -ldflags "-X github.com/yaleh/meta-cc/cmd.Version=$(VERSION) \
                     -X github.com/yaleh/meta-cc/cmd.Commit=$(COMMIT) \
                     -X github.com/yaleh/meta-cc/cmd.BuildTime=$(BUILD_TIME)"
```

`LDFLAGS` is used at `Makefile:515` (cross-compile loop), `Makefile:553` (`install:` target, `go
install $(LDFLAGS) ./cmd/mcp-server`), and `Makefile:560` (`cross-compile:` target) — all building
`./cmd/mcp-server`. But:

- There is **no `github.com/yaleh/meta-cc/cmd` package at all**: `ls cmd/` shows only a `mcp-server/`
  subdirectory, no `.go` files directly under `cmd/`. `github.com/yaleh/meta-cc/cmd/mcp-server` is a
  different import path than `github.com/yaleh/meta-cc/cmd`.
- `grep -rln "BuildTime\b" --include=*.go .` across the entire repository returns **zero matches** —
  no Go source file anywhere declares a `BuildTime` (or `Commit`, outside test files) variable for
  `-X` to target.
- Reproduced directly: building `./cmd/mcp-server` with the exact `-X
  github.com/yaleh/meta-cc/cmd.Version=... -X github.com/yaleh/meta-cc/cmd.Commit=... -X
  github.com/yaleh/meta-cc/cmd.BuildTime=...` flags used by `make install`/`make cross-compile`
  produces **no linker warning or error at all** — the build silently succeeds and the resulting
  binary embeds none of `VERSION`/`COMMIT`/`BUILD_TIME`. `cmd/mcp-server/main.go:32-34` only logs
  `version.Version` (the `internal/version` package's `go:embed`'d `release.json` value, per
  `internal/version/version.go`) — never `COMMIT`/`BUILD_TIME` in any form.

So the one piece of Makefile machinery that looks purpose-built to answer "what commit/build is this
binary" has been dead since it was introduced (it targets a package path that has apparently never
existed for `cmd/mcp-server`), and nobody has noticed because Go's `-X` flag failure mode for an
unresolvable symbol is silent, not a build failure. This directly explains why the DIR-048 "done" fix
is invisible in this live session: the currently-loaded MCP server binary is provably older than the
fix, and there is no signal — not the version string, not a commit hash, not a build timestamp
anywhere in logs/`--version` — that would let anyone (human or agent) detect that skew without
manually correlating `stat`/`ps` timestamps against `git log` the way this investigation did.

This is distinct from the already-filed/fixed items in this area:
- DIR-025 ("establish one release version and MCP capability source of truth") only makes the
  hand-bumped release *number* consistent across manifests — it does not, and by design cannot,
  distinguish two different commits that both ship under the same un-bumped release number.
- DIR-037 ("harden make stage/install-user for live-process safety") fixes the `cp`→ETXTBSY race and
  Codex TOML registration; it does not address commit fingerprinting or freshness detection.
- DIR-041/042/043/044/046/047/048 are all *source-level* dead-parameter-wiring defects, already fixed
  on `main` — this finding is that the *deployed artifact* used to validate those very fixes can be
  stale, and nothing announces that.

## Proposal

1. Fix the dead LDFLAGS to target real symbols: add `Commit`/`BuildTime` (and reuse the existing
   `Version`) vars to `internal/version` (or a small new `internal/buildinfo` package actually
   imported by `cmd/mcp-server`), and point `Makefile`'s `-X` flags at
   `github.com/yaleh/meta-cc/internal/version.Commit=$(COMMIT)` /
   `...version.BuildTime=$(BUILD_TIME)` instead of the nonexistent `github.com/yaleh/meta-cc/cmd.*`.
2. Log `commit`/`build_time` alongside `version` in `cmd/mcp-server/main.go`'s "MCP server starting"
   entry, and expose them via a cheap capability surface (e.g. `get_session_metadata` or a
   `--version` CLI flag) so a caller can answer "is this server built from current HEAD" without
   shell access.
3. Add a regression test/gate that fails loudly if an `-X` linker flag target doesn't exist (e.g.
   assert the built binary's embedded commit is non-empty/non-"unknown" in a `make commit`-run test),
   closing the "silent no-op linker flag" failure mode generally, not just for this one instance.
4. Optionally, document (and/or gate) that `make install-user`/`make install-local` must be re-run
   after any `main` change that affects MCP tool behavior, since nothing today automatically keeps a
   user-scope install in sync with new commits — the DIR-037 write-up already reproduces the adjacent
   "two clients silently end up on different binaries" problem; this is the same class one layer up
   (one client silently ends up on an old binary of itself).

## Acceptance Criteria

- [ ] `github.com/yaleh/meta-cc/internal/version` (or equivalent) exposes non-empty `Commit` and
      `BuildTime` values when the binary is built via `make install`/`make cross-compile`/`make
      build`, sourced from the Makefile's existing `COMMIT`/`BUILD_TIME` shell-derived variables.
- [ ] `cmd/mcp-server`'s startup log includes `commit` and `build_time` fields alongside `version`.
- [ ] A committed Go test fails if the embedded commit is empty/"unknown" for a build produced by the
      real `make install`/`make build` LDFLAGS (i.e., proves the `-X` wiring actually resolves).
- [ ] Deliberately reverting the `-X` target back to a nonexistent package path makes that test fail
      (proves the test is not vacuously passing).
- [ ] `go test ./internal/version/... ./cmd/...` and `make commit` pass.

## Definition of Done

- [ ] The fix is landed on `main` (not left in a worktree), and a rebuilt `make install-user` binary's
      startup log demonstrably shows a `commit` field matching `git rev-parse --short HEAD` at build
      time.
- [ ] `docs/guides/release-process.md` and/or `docs/guides/plugin-development.md` document that
      commit/build-time are now embedded and how to read them, and note that a user-scope install
      must be refreshed via `make install-user` to pick up new commits.
- [ ] `make commit` passes.
