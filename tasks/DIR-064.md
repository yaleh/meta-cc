# Codex appendUnknown stamps turns with query-time time.Now(), not the event time → records carry today's date, breaking time filters

## Finding

When the Codex rollout parser hits an unrecognized event while no turn is open, `appendUnknown` creates a turn stamped with the *query-time* wall clock (`time.Now()`) rather than the event's own timestamp. The event's timestamp is parsed only for the Item, never for the Turn. `Normalize` emits the Turn's timestamp as the record `timestamp`, so real historical records (e.g. from 2025) carry today's date — breaking `since`/`until` filtering and recency sorting for any session that begins with (or contains a gap before) an unknown event.

Source — `internal/provider/codex/rollout.go:588-601`:
```go
func (b *turnBuilder) appendUnknown(line []byte) {
    b.ensureTurn("", time.Now().UTC().Format(time.RFC3339))   // line 589 — query time, not event time
    b.unknown = append(b.unknown, append(json.RawMessage(nil), line...))

    var stamped struct{ Timestamp string `json:"timestamp"` }
    _ = json.Unmarshal(line, &stamped)
    ts := parseTimestamp(stamped.Timestamp)                    // event time parsed here...
    if ts.IsZero() {
        ts = b.current.Timestamp                               // ...but the turn already holds now()
    }
    b.current.Items = append(b.current.Items, conversation.NewRawItem(conversation.ItemKindUnknown, ts, line))
}
```
`appendUnknown` is reached from the `default` case (rollout.go:579) and `turn.failed`/`error` (line 576) — exactly the schema-drift case it exists for (an unknown top-level event before the first `turn.started`). When that unknown event creates the turn, `b.current.Timestamp = now()`. `Normalize` then writes that as the record timestamp (records.go), so a 2025 session queried in 2026 reports 2026 timestamps; the Item-level fallback at line 598 also inherits the bogus now-value when the item itself has no timestamp.

Trigger: any rollout whose first event is unrecognized (new Codex event family the parser doesn't know about — the precise scenario `appendUnknown` is designed to tolerate), or an unrecognized event after a `turn.completed` flush. The fix the code intends (preserve unknown events) silently corrupts time metadata.

## Proposal

1. Derive the turn timestamp from the event: parse `line`'s `timestamp` first and pass it to `ensureTurn`; fall back to `time.Now()` only if the event truly has no timestamp (and ideally mark such turns as time-unknown).
   ```go
   ts := parseTimestamp(extractTimestamp(line))
   if ts.IsZero() { ts = time.Now().UTC() }   // last resort, not first
   b.ensureTurn("", ts.Format(time.RFC3339))
   ```
2. Reuse one timestamp-extraction helper for both the Turn and the Item so they agree.
3. Add a regression test: an unknown first event with a 2025 timestamp must produce a turn/record timestamped in 2025, independent of when the test runs.

## Acceptance Criteria

- [ ] A rollout whose first line is an unrecognized event carrying `timestamp: "2025-03-01T00:00:00Z"` produces a turn/record with a 2025 timestamp, not the current date.
- [ ] The Item and its enclosing Turn carry the same (event-derived) timestamp when the event has one.
- [ ] A regression test in `internal/provider/codex` asserts the record timestamp equals the event timestamp (run-time-independent).
- [ ] `go test ./internal/provider/codex/...` passes; `make commit` passes.
