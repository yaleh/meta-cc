## Finding

Measured 2026-07-30: the two slowest individual tests in the suite are
dual-scan parity comparisons, both in
`internal/mcp/executor/fts_content_e2e_test.go`:
`TestQuerySessionContent_FTSParityWithCanonicalScan` (5.3s) and
`TestQuerySessionContent_UnicodeCaseFoldingParity` (4.3s) — together 9.6s of
serial wall time on every short run. They exist to prove the FTS/Unicode fast
path agrees with the canonical scan; that guarantee matters on the full path
(`make push` / CI), not on every `make commit` cycle.

Context: `go test -short -count=1 ./...` takes 46.3s total (executor alone
34.2s, 74%). `make commit` ≈62s; since 2026-07-28 there have been 79 acceptance
gate runs (≈82 min total wait, DIR-056 alone ran acceptance 9 times), so every
second removed from `-short` compounds across the whole gate history.

### Verification round 2026-09-17 (continuation) — the suite failure was the reported race, now fixed

**Entry state.** Branch `task/DIR-083` carried 3 commits already (head: merge of
`develop`); all 4 AC were checked. Fan-in had exited **not-landed twice**, both
times on `step=suite`:
`--- FAIL: TestBuildResponse_FileRefCarriesSelfDescribingMetadata`.

**True cause: the cross-package temp-dir race reported in the previous
subsection — same defect, different victim.** The fan-in suite log
(`.quay/fan-in-suite-DIR-083~wk-prod-anchor~1789634849084-292a51.log`) reads:

```
--- FAIL: TestBuildResponse_FileRefCarriesSelfDescribingMetadata (0.00s)
    pipeline_fileref_shape_test.go:81:
        Error: Received unexpected error:
            open /data/scratch/yale/meta-cc-mcp-unknown-1789634849834145169-query_session_content.jsonl: no such file or directory
```

That test spills to `file_ref` and then `os.ReadFile`s the file it just wrote
(`internal/mcp/pipeline/pipeline_fileref_shape_test.go:81`). Same signature as
the previously reported `cmd/mcp-server` victim: the file is unlinked between
write and read, by a *different package's* test. The earlier round guessed the
victim set was `cmd/mcp-server` only; it is every package that holds a live
`meta-cc-mcp-*.jsonl`, which is why the flake reappeared on a new test.

**Mechanism, re-confirmed by direct measurement rather than inference.**

- `CleanupOldFiles(maxAgeDays)` resolves its threshold as
  `time.Now().Add(-maxAgeDays)` and globs `os.TempDir()/meta-cc-mcp-*.jsonl`
  un-namespaced (`internal/mcp/response/output_manager.go:132-159`). The `-1`
  sentinel therefore computes `now+24h` and matches **everything**.
- Direct check of the blast radius: stage canary files in
  `/data/scratch/yale`, run the response package, count survivors —
  **0/3 survive before the fix, 3/3 after**.
- Direct check of the race itself, the exact fan-in test against a concurrent
  response-package run, 40 iterations: **4 failing runs before the fix,
  0/40 after**.
- Only two call sites pass a value that can match a fresh file:
  `adapter_test.go` (`CleanupOldFiles(-1)` in `t.Cleanup`) and
  `output_manager_test.go` (`ExecuteCleanupTool(max_age_days=-1)`). Every other
  caller uses `7` (`cmd/mcp-server/*`), which cannot reach a fixture written
  seconds earlier.

**Fix — commit `3693c16`, test-only, 2 files, +17/−2.**

- `adapter_test.go`: the blanket `t.Cleanup(CleanupOldFiles(-1))` is replaced by
  removing only the file that test created. The cleanup now cannot reach another
  package's fixture by construction, not by timing.
- `output_manager_test.go`: `ExecuteCleanupTool` is still exercised end to end,
  but with a threshold that admits nothing (`3650`), because any value that can
  actually match a file re-creates the same cross-package deletion from a
  different direction — a small day count would instead eat `cmd/mcp-server`'s
  8-day-old staged fixture in `TestCleanupOldFiles`. The removal path it used to
  cover is still asserted immediately above it via `CleanupOldFiles(1)`
  (`assert.Contains(t, removed, oldPath)`), so coverage is preserved.
- Not changed: `CleanupOldFiles` itself. It is the production implementation
  behind the `cleanup_temp_files` tool; its glob and its `-1` "no age limit"
  sentinel are the tool's intended semantics. The defect was two tests using a
  whole-directory sweep as per-test cleanup, so the fix belongs at the call
  sites.
