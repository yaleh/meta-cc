## Finding

Measured 2026-07-30: the two slowest individual tests in the suite are
dual-scan parity comparisons, both in
`internal/mcp/executor/fts_content_e2e_test.go`:
`TestQuerySessionContent_FTSParityWithCanonicalScan` (5.3s) and
`TestQuerySessionContent_UnicodeCaseFoldingParity` (4.3s) — together 9.6s of
serial wall time on every short run. They exist to prove the FTS/Unicode fast
path agrees with the canonical scan; that guarantee matters on the full path
(`make push` / CI), not on every `make commit` cycle.

34.2s, 74%). `make commit` ≈62s; since 2026-07-28 there have been 79 acceptance
gate runs (≈82 min total wait, DIR-056 alone ran acceptance 9 times), so every
second removed from `-short` compounds across the whole gate history.

**Baseline blocker: the worktree is correct; the defect is the `develop` ref,
and the repair is not the one the gate prints.**

- The wedge persists and is workspace-wide: `git merge-base --is-ancestor main
  develop` is false, `git rev-list --count develop..main` = 1 (the stranded
  `task_write` commit). Against current `develop`, DIR-082/083/084/093/097/098
  **all six** worktrees exit with the identical BASELINE-MISMATCH — this is not
  a DIR-083 defect.
- The gate's printed remedy (`quay init --force --adopt-branch-model`, i.e.
  re-point `develop` at `main`) is **destructive** here. Probed read-only with
  `--merge-target main`: `ANTI-DRIFT HARD FAIL — 5 violation(s)`, out-of-declared
  on `CLAUDE.md`, `Makefile`, `docs/guides/plugin-development.md`,
  `docs/guides/testing.md`, `tasks/DIR-090.md`. A task branch forked from the old
  `develop` line carries other tasks' landed work, so re-pointing `develop` at
  `main` re-attributes that work to this task. **Do not run it.**
- The correct repair is `develop := merge(main, develop)` — non-destructive
  (`main` becomes an ancestor, nothing is dropped). Proven conflict-free and
  sufficient **without moving any ref**:
  ```
  TREE=$(git merge-tree --write-tree main develop)      # rc 0, tree 16263af6
  PROBE=$(git commit-tree "$TREE" -p main -p develop -m probe)
  anti-drift-touches-check --task DIR-083 --worktree .worktrees/DIR-083 \
    --merge-target "$PROBE"
  → ANTI-DRIFT OK: task DIR-083 — 2 actual file(s), all within declared Touches
  ```
  So nothing but the `develop` ref move stands between this task and fan-in.
  That move is a workspace-level action owned by the outer layer (and racing the
  driver's own ff push is a real risk), so it was deliberately not performed
  here. **Requested of the outer layer: `develop := merge(main, develop)`, then
  re-dispatch.** Note the repair is only temporary — the ff-push trigger that
  re-arms it recurs on the next fan-in merge.
