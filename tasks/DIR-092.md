## Finding

meta-cc analyze_bugs / analyze_errors over 2026-07-25..07-30 show two
recurring pre-commit infrastructure failures that waste agent round-trips:

- goimports pre-commit hook modifies files mid-commit, producing
  "files were modified by this hook" and failing the commit; the agent
  must then re-add and re-commit (2 recurrences, signature 42cdfb0d9cb2f9c5).
- `/usr/bin/python3: No module named pre_commit` — the hook framework is
  referenced by the git hooks but not installed (2 recurrences, signature
  d6e9126e6892fece).

Both are deterministic, mechanical fixes that remove needless retry loops.

## Dependencies

None.

## Proposal

**What/Why**: Two deterministic pre-commit defects waste agent round-trips. (1) The `go-imports` hook (`.pre-commit-config.yaml:20-23`) runs with `args: [-w, -local=github.com/yaleh/meta-cc]` — the `-w` flag rewrites staged files mid-commit, so the framework aborts with "files were modified by this hook" and forces a re-add/re-commit; there is no re-stage step and no warn-only demotion anywhere in the config. (2) `scripts/install/install-pre-commit.sh:13-22` only checks for a `pre-commit` binary on PATH (`command -v pre-commit`) and `exit 1`s with "❌ pre-commit not found" — it never installs the `pre_commit` Python module and cannot detect a module-based install. Verified mechanically: `command -v pre-commit` → exit 1 (no binary on PATH) while `/usr/bin/python3 -c "import pre_commit"` → OK and `python3 -m pre_commit --version` → `pre-commit 4.6.1`; so `make install-pre-commit` (`Makefile:725-727`, which only runs that script) fails today even though a working module exists, and makes the module present on no fresh checkout. The generated hook `.git/hooks/pre-commit` execs `INSTALL_PYTHON=/usr/bin/python3 -mpre_commit`, which is exactly the path that emits `No module named pre_commit` when the module is absent. `docs/guides/git-hooks.md` documents none of this flow (no `install-pre-commit`, `make fmt`/`make fix-imports`, or warn-only mention).

**Approach**:

1. In `.pre-commit-config.yaml:20-23`, remove the rewrite behavior of the `go-imports` hook by dropping the `-w` arg (keep `-local=...`), so it becomes check-only and can no longer modify staged files mid-commit — this is Plan step 1(b)'s warn-only/non-failing demotion.
2. Document `make fix-imports` (`Makefile:304-306`, `goimports -w .`) and `make fmt` (`Makefile:716-718`, `gofmt -l -w .`) as the intended pre-commit formatting step, so formatting happens before staging rather than inside the hook.
3. Rewrite `scripts/install/install-pre-commit.sh:13-22` to be module-aware and install-then-verify: detect the module via `python3 -c "import pre_commit"`; if missing, install it (`python3 -m pip install --user pre-commit`, falling back to a venv); verify via `python3 -m pre_commit --version`; and on any failure print the exact one-line remediation command and `exit 1`.
4. In the same script, when no `pre-commit` binary is on PATH, invoke the framework as `python3 -m pre_commit install` (and `... run --all-files`) instead of the bare `pre-commit` used at lines 48/62, matching the verified binary-absent/module-present reality.
5. Keep the `install-pre-commit` Makefile target (`Makefile:725-727`) delegating to the script; confirm the `make help` line (`Makefile:795`) stays accurate — no recipe change required beyond the script fix.
6. Update `docs/guides/git-hooks.md` to describe the intended flow: run `make install-pre-commit` once; run `make fix-imports`/`make fmt` before commit; and which hooks are check-only vs. failing.
7. Verify both AC paths locally: on a fresh checkout `make install-pre-commit` succeeds or fails with a single-line fix instruction, and a commit containing deliberately unformatted imports lands in ONE attempt.

**Out of scope**:

- All other hooks in `.pre-commit-config.yaml` (golangci-lint `:33-41`, gosec `:46-52`, go-test `:58-65`, marketplace/version `:67-93`, pre-commit-hooks `:108-140`) — only the `go-imports` rewrite behavior and the module install path change.
- Migrating to a different hook framework or touching CI workflows.
- Other `scripts/install/*` scripts and the plugin-version `.githooks/pre-commit` flow documented in git-hooks.md.

**Risks**:

- Dropping `-w` makes the goimports hook report-only, so developers who relied on auto-formatting at commit time must run `make fix-imports` first; mitigated by the doc update and the preserved check output naming offenders.
- `pip`/venv availability varies across machines, so the install step can still fail in locked-down environments; mitigated by the fail-closed exact-remediation message (AC #2 keeps the ModuleNotFoundError path unreachable either way).

## Plan

1. Fix the goimports rewrite loop. Either (a) keep the hook but run it at a
   pre-staged stage that re-stages modified files before the commit proceeds,
   or (b) make `make fmt` / `make fix-imports` the documented pre-commit
   step and demote the goimports hook to warn-only (non-failing) so it no
   longer rewrites files mid-commit.
2. Fix the missing module. Make `make install-pre-commit` actually install
   the `pre_commit` python module (e.g. `python3 -m pip install pre-commit`
   in a venv), or, if installation is not possible, fail loudly with the
   exact install command to run. The ModuleNotFoundError path must be
   unreachable: install-then-verify, or a clear one-line remediation message.
3. Update docs/guides/git-hooks.md to describe the intended flow (run
   `make install-pre-commit` once; the documented pre-commit formatting
   step; warn-only vs. failing hooks).
