# Root Cause Analysis: query_summaries Returns Null

## Symptoms

In large projects (e.g., `/home/yale/work/baime` with 126 session files, ~70MB):
1. `query_summaries` returns `{"data":null,"mode":"inline"}` instead of matching records.
2. `get_timeline` outputs 737K+ characters causing Claude Code context truncation.

## Root Cause

### Bug 1: query_summaries null return

The old `query_summaries` tool used the jq filter:
```jq
select(.type == "summary")
```

However, Claude Code's JSONL format **never creates records with `type: "summary"`**. A survey of 127 session files in the baime project confirmed zero records with `type: "summary"`.

The actual session summaries generated by Claude Code are embedded inside `type: "assistant"` records as content blocks:
```json
{
  "type": "assistant",
  "message": {
    "content": [
      {"type": "text", "text": "## Summary\n\nWork done in this session..."}
    ]
  }
}
```

This schema mismatch causes the jq filter to match zero records, resulting in `QueryResult.Entries` being `nil`. When serialized via `BuildInlineResponse`, a nil slice marshals to JSON `null`:
```json
{"data": null, "mode": "inline"}
```

**Contributing factors:**
1. Wrong jq filter: `select(.type == "summary")` — type "summary" does not exist in Claude Code JSONL
2. Nil slice propagation: `QueryResult.Entries` (nil) → `BuildInlineResponse(nil)` → `"data": null`

### Bug 2: get_timeline context truncation

`GetTimeline` in `internal/analysis/service.go` auto-limits to 500 events when entry count > 2000:
```go
if limit == 0 && stringArg(args, "scope") != "session" && len(entries) > 2000 {
    limit = 500
}
```

However, with 126 sessions and large assistant messages (baime averages ~345 entries per session × 40KB per entry), even 500 events can produce 737K+ characters of JSON output, far exceeding the safe inline threshold.

Additionally, there is no `since`/`until` time-clipping to allow users to query a specific date range.

## Fix Plan

### Fix 1: query_summaries (Phase 2)

1. `internal/mcp/pipeline/pipeline.go`: Add `query_summaries` to `TimestampStatsTools` map with documentation comment explaining the root cause and correct replacement.
2. `internal/mcp/response/adapter.go`: Ensure `BuildInlineResponse` returns empty array `[]` instead of `null` when data is nil.
3. `internal/mcp/executor/consolidated_handlers.go`: Harden the `role=assistant` jq filter with `// empty` guards for null content.

### Fix 2: get_timeline (Phase 3)

1. `internal/analysis/service.go`: Add `since`/`until` ISO 8601 time-clipping parameters.
2. When no since/until and entry count > 1000, default to stats summary mode.
3. `internal/mcp/tools/tools.go`: Expose `since`/`until` params in the `get_timeline` tool schema.

## Verification

After fix, the following should hold:
- `query_session_content({role:"assistant", contains:"## Summary"})` returns non-null `data` array
- `BuildInlineResponse(nil)` returns `{"data":[],"mode":"inline"}` not `{"data":null}`
- `get_timeline` with large project returns stats summary by default, not full event stream
- `get_timeline(since="2026-01-01T00:00:00Z")` correctly clips to that date range
